# qlib 路线：数据口径与验收门槛（初版）

> 信息仅供参考，不构成投资建议。

**定位**：这份文档是 `scripts/qlib_export_kline.py` + `scripts/qlib_run.py` 这条 qlib 链路的
**口径真源**。链路从 Mongo 原始日线一直走到回测和最新日选股，中间每一步的取舍都写在这里。
以后要改窗口、改票池、改标签，先改这份文档，再改代码。

写它的直接原因：本次迁移的动机是**「如果无法量化，那做一切都没有意义」**。
既然要靠量化下结论，就必须先把「什么算通过」定死，否则跑出来的数字会被反向解释成想要的答案。
门槛在看到留出段结果之前登记，看完结果之后不许回头改。

## 一、链路全貌

```
Mongo stock_kline (原始日线, qfq)
      │  scripts/qlib_export_kline.py     ← 摊成「日历稠密」CSV
      ▼
/data/work/qlib_data/csv/<SYM>.csv
      │  qlib/scripts/dump_bin.py dump_all
      ▼
/data/work/qlib_data/cn/{calendars,instruments,features}
      │  scripts/qlib_check_panel.py       ← 逐点比对 bin vs Mongo，证明转换没失真
      ▼
      │  scripts/qlib_run.py
      ├─ Alpha158 因子 → LGBModel 训练
      ├─ 横截面 rank IC / 五分位  ← 验收门槛 A（有没有信息）
      ├─ TopkDropout 回测（不平移信号，见 §4） ← 验收门槛 B（扣成本赚不赚钱）
      └─ 最新交易日选股名单
```

三段命令（顺序执行，别跳步）：

```bash
python3 scripts/qlib_export_kline.py --out /data/work/qlib_data/csv --first-year 2015
python3 /data/work/qlib/scripts/dump_bin.py dump_all \
  --data_path /data/work/qlib_data/csv --qlib_dir /data/work/qlib_data/cn \
  --freq day --max_workers 4 \
  --include_fields open,high,low,close,volume,amount,vwap,factor
python3 scripts/qlib_run.py --universe 300 --backtest
```

## 二、数据口径（六条，每条都是踩过坑之后定下来的）

### 1. 源只用 Mongo，不用 parquet，也不下载 cn_data

`data/` 下那套预计算 parquet 是有断档的（2023-01→2026-05 大片缺失）。Mongo 的 `stock_kline`
反而更全，所以 qlib 的地板直接铺在 Mongo 上。

### 2. `frequency` 必须同时取 9 和 0，两批是互补的

- `frequency=9`：主批，6,948 只，1999-03-23→2026-10-16。
- `frequency=0`：补洞批，3,121 只，2022-10-24→2026-05-06。

**踩过的坑**：只取 9 的话，600519 在 2023、2024 两年整年空白（810/2,637 行为空），
训练时模型看到的是「这只票停顿了两年」——这就是假停牌。合并两批之后全量导出实测
`written=6,937 / skipped_short=11`，空洞率 **1.47%**（分母是每只票首末交易日之间的
日历格数，不是全表；这些洞绝大多数是真实停牌与上市前），重复 (代码,日) 行 **511 行**
（12.21M 总量里占 0.004%，都是同一批重复抓取留下的，按 `crawl_time` 取最新一条即可）。
注意：早期我在 5 只票的抽样上读到过 `duplicate_rows=0`，那个 0 只代表抽样，
不代表全表——全量是 511 行。

### 3. CSV 必须摊成「日历稠密」，缺日留空

`dump_bin.py dump_all` 的 `_dump_bin` 是 `np.hstack([date_index, field])` ——
它**只按行序写值，不会 reindex 到日历**。所以 CSV 少一天，后面每一天全部错位，
而且错得悄无声息。这就是 `dense_frame()` 存在的唯一理由：先按 5,426 天交易日历
把每只票拉满，缺失日留 NaN，让 bin 里的第 n 行永远对应日历第 n 天。

### 4. volume 一律换算成「股」，vwap 用 amount/volume 反算

逐年实测 `amount/(volume(手)×close)` 的中位数在 100 上下（2014→2026 主板/创业板/
科创板/基金都成立），说明库里 volume 单位是**手**。导出时 ×100 换成股。
`vwap = amount / volume(股)`，算不出来（量或额缺、或算出非正数）就退回 `close`——
qlib 只把 vwap 当日内分布因子，退回 close 不改变量纲。

### 5. `factor` 恒为 1，因为源本身就是 qfq

源已经前复权过，qlib 再乘一遍 factor 就是双重复权。
**必须记住的代价**：qfq 是**锚在抓取日**的，每次分红之后整条价格绝对水平会重标。
所以只用相对量（收益率、比值、排名），绝不把绝对价位跨时间比。

### 6. 基准用 `SH510300`（沪深300ETF，qfq 价），不是指数

- 面板里**没有**上证综指/沪深300 指数序列：`000xxx` 会和深市股票 code 撞名，
  唯一 (code,date) 索引证明它从没入库。
- `399xxx` 深市指数**只有 2025-01-20→2026-10-16 的 419 行**（爬虫只留近端），
  2021/2023 的回测窗口直接无数据——qlib 会在建账户时就抛
  `The benchmark [...] does not exist`。
  （本条更正了本文档更早写的「SZ399001 是唯一可用基准」，那句是错的。）
- 可用的是宽基 ETF：`SH510300` 2,637 行、2015-12-07→2026-10-16 连续，覆盖全部窗口。

**口径必须说清**：510300 是**基金的前复权价**，不是指数——分红被折进价格里，
所以它更接近沪深300 的**全收益**口径；而且它代表大盘股，本票池的前 30 名偏中盘，
用它当基准对中小盘策略是**偏高**的尺子。所有「超额收益」都是**对 510300** 的超额。

## 三、票池口径：只用训练段排序，不看未来

- 股票前缀 `60/68/00/30`，剔掉基金、指数、B 股、北交所。面板 6,937 只里符合号段的是 **5,206 只**。
- 票池 = **训练窗口内**日均 `amount` 排名前 N。

为什么不用全历史或当前市值排序：那是**用未来选今天的样本**，等于幸存者偏差换了个入口。
也没有历史指数成分数据可用（`hs300_stocks.csv` 只是当前快照）。

### 初版 N=300，是硬件逼出来的，不是设计选择

本机可用内存 ~5.5–6G（WiredTiger 限 2G、celery 限 3G cgroup、还有 earlyoom 会去杀别的进程）。
实测：`--smoke`（120 只 × 2019-2021 = 87,600 行）峰值 RSS 670 MB，扣掉 Python+qlib+pandas
的 ~350 MB 底板，**每个样本行约 3.65 KB**（Alpha158 158 列 float32 本身 632 B/行，
剩下是 raw/infer/learn 三份拷贝 + LightGBM 自己的直方图缓冲）。

按这个单价：

| 票池 | 2016-01→2026-10 行数 | 预估峰值 |
|---|---|---|
| 800 | ~210 万 | **~8 GB → 装不下** |
| 300 | ~79 万 | ~3.2 GB（初版采用） |
| 100 | ~26 万 | ~1.3 GB |

所以初版把 N 从 800 改成 **300**。这不是看到结果之后调的，是跑冒烟之前量出来的，
改在留出段被读之前；代价也说清楚：**300 只最流动的票约等于自造一个沪深300 近似池**，
读出来的是「大盘股里 Alpha158 还有没有信息」，不代表中小盘。
要上 800/全市场，得先换机器或者把 Alpha158 砍成子集（那就不是 qlib 的标准因子集了）。

为什么必须限票池而不是全市场：全市场 10 年 Alpha158 是 ~1,200 万行 × 158 列 float32 ≈ 7.6G，
本机只剩 ~4G 可用（WiredTiger 限 2G、celery 限 3G、还有 earlyoom）。全市场跑起来只会 OOM，
不会跑出结果。

## 四、防前瞻红线（与项目主红线一致）

**T 日数据只能驱动 T+1 决策。** 这条在 qlib 里有两处要盯：

1. **标签**：`Ref($close,-5)/Ref($close,-1)-1`
   = T 日收盘特征 → T+1 收盘买入 → T+5 收盘卖出。不是 `Ref($close,-1)/$close-1`，
   那个等于用 T 日特征买 T 日收盘价。
2. **回测刻意不再平移信号**。源码查证：`qlib/backtest/utils.py:128`
   `get_step_time(trade_step, shift=1)`，注释写明「shift > 0 取更早一根」，
   而 `TopkDropoutStrategy.generate_trade_decision` 正是用 `shift=1` 取信号窗口。
   也就是说 **qlib 在交易日 T 决策时读的是 T−1 日的分数，按 T 日收盘成交**。
   设特征日 F，则 T=F+1 成交，成交价 = F+1 收盘 = 标签的买入价，两侧天然对齐。
   如果再手动把分数后移一天，就变成 F+2 成交却拿 F+1 的标签算收益——口径错位，比前瞻更隐蔽。
   （代价：回测第一个交易日找不到前一日的分数，那天不开仓，只影响首日。）
3. **回测结束日不能是日历最后一天**。同一个 `get_step_time` 还要取
   `self._calendar[calendar_index + 1]` 当区间右端点；`2026-10-16` 正好是本次日历最后一根，
   跑到那一步直接 `IndexError: index 2862 is out of bounds for axis 0 with size 2862`。
   `qlib_run.py` 因此把撮合窗口截在**倒数第二根 K 线**（读数里的 `window` 字段就是实际窗口），
   最后一天只用来出选股名单。这是 qlib 需要「未来日历」的限制（日志会警告
   `load calendar error: freq=day, future=True`），不是策略问题。

资金流信号接进来时同样受这条约束：`date` 分区必须再滞后一天，且回测撮合要沿用
`executability.py` 的涨停买不进/一字板卖不掉。

## 五、验收门槛（先看 A，A 不过不看 B）

### 门槛 A —— 特征集里到底有没有信息

| 指标 | 通过线 | 口径说明 |
|---|---|---|
| 验证段横截面 rank IC 均值 | > 0.02 | 逐日 Spearman，一天一个横截面 |
| ICIR（IC 均值/IC 标准差） | > 0.2 | 只看均值会把高方差也蒙过去 |
| IC 的 t 值 | > 2 | 天数就是样本量，别拿 3 个月的均值当结论 |
| 五分位单调性 | 头→尾递减，且 Q5-Q1 的 t > 2 | 只看 Q5 会漏掉「只有尾部有效」 |

**A 不过，就不许谈 B。** 历史上这条线被踩了太多次：C 模型 12 格 0 过、D 模型两臂 24 格 0 过，
每次都是「IC 看着像正的」而条件概率根本不可用。

### 门槛 B —— 扣完成本赚不赚钱

TopkDropout（topk=30、n_drop=5），`open_cost=0.0005`、`close_cost=0.0015`、`min_cost=5`、
`limit_threshold=0.095`（涨跌停限制成交）。

| 指标 | 通过线 |
|---|---|
| 测试段年化超额（对 `SH510300`，**扣成本后**） | > 0，且留出段各年度中位数 > 0 |
| 最大回撤 | 报告必带，不设门槛，但不许只报收益不报回撤 |
| 换手 | 报告必带：换手决定了毛 α 会不会被成本吃干净 |

**仪器警告（2026-10-18 加，我自己踩过）**：qlib `report["return"]` 是**扣成本前**的毛收益
（`backtest/account.py:283` 把手续费加回去了），门槛 B 要用的是 `report["account"]`（现金+持仓市值，
成本已扣）。验收前必须让净值曲线自证「起点=初始本金、终点=最后账户总值」——这两点对不上就是取错列。

三个已知会致死的坑，报数字时必须一起说明：
1. **样本量**：30 只票 × 测试段天数，年份切片很容易不足 30 笔，不足就明说「无区分度」。
2. **抽样不稳**：`pattern_reversal` 那次是同一天基线 +0.5/+0.4pp，换一批股票直接翻负。
   所以票池换一个随机种子必须重跑一遍对照。
3. **成本中性 ≠ 赚钱**：剔除层那种「成本中性 +2.9~5.4%/yr」是少亏，不是赚。

## 六、报告纪律

每次跑完写 `data/qlib/run_<id>.json`，里面必须同时有：窗口日期、票池大小与构造方式、
门槛 A 全部指标、门槛 B 全部指标、以及本次**没有**满足的门槛。

不许出现的表述：
- 「IC 为正，说明有效」（0.005 的 IC 也是为正）。
- 只报一个百分比不带口径（分子分母、时间窗、票池都要跟着）。
- 用回测收益解释选股逻辑（先过门槛 A）。

## 八、初版读数（2026-10-18 07:52，`data/qlib/run_20261018-075005.json`）

一次跑通全链路：Mongo → CSV（6,937 只）→ bin → Alpha158 → LightGBM → IC/分档 → TopkDropout 回测 → 名单。
配置：票池 300（训练段流动性前 300）、训练 2016-01-01→2021-12-31、验证 2022 全年、
测试 2023-01-01→2026-10-16、`topk=30 n_drop=5`、成本买 5bp/卖 15bp/最低 5 元、涨跌停 9.5% 不成交。
LightGBM 早停在第 **61** 棵（valid l2 0.9935），80 轮后开始过拟合。

**先说一条通用口径**：下面所有「逐日序列的 t」都被 5 日重叠窗口放大了。标签是 T+1→T+5 的收益，
相邻 5 天的样本互相重叠，标准差被低估约 √5 倍，所以 **把原始 t 除以 2.24** 才是接近真实的读数
（前提：日收益近似独立；A 股短周期自相关偏弱，这个校正偏保守但不离谱）。

### 门槛 A —— 过了，但只有一条勉强

| 预注册线 | 原始读数 | 重叠校正后 | 判定 |
|---|---|---|---|
| 测试段 rank IC 均值 > 0.02 | **0.0432**（910 天，横截面中位 300 只） | — | 过 |
| ICIR > 0.2 | **0.316**（IC 日 std 0.1364） | — | 过 |
| IC t > 2 | 9.55 | **4.27** | 过 |
| 五分位单调 | Q0 −0.121% → Q1 +0.068% → Q2 +0.121% → Q3 +0.157% → Q4 +0.209%（5 日收益，逐日均值） | — | 过 |
| 最好档−最差档 t > 2 | 同日配对 **5.28** | **2.36** | 勉强过 |

验证段（2022 单年，242 天）更高：rank IC 0.0636、ICIR 0.449、t 6.98（校正后 3.12）。
测试段正 IC 天数占比 62.0%。

**必须承认的一处事后改动**：预注册只写了「Q5−Q1 的 t > 2」，没写用什么 t。
脚本原来算的是**两档各自标准差合并**的 t = 1.61（校正后 0.72，不过线）；
我看到它不过之后才补上**同日配对** t（5.28）。配对在方法上是对的（同一天里相减，大盘波动已经抵消，
合并标准差的算法把它重复计进去了），但**改口径发生在看到结果之后**，所以这条不能当定论：
下一轮必须在独立样本（换票池抽样或换测试段年份）上先看配对 t，才对得上「预注册」两个字。

### 门槛 B —— **没过**（2026-10-18 事后修正：原来贴的是扣成本**前**的毛收益）

先说错在哪。门槛 B 预注册写的是「**扣成本后**年化超额 > 0」，而脚本取的是 qlib
`report["return"]` 列——那一列**不是**净值。qlib 源码 `backtest/account.py:283` 写的是
`return_rate = (earning + cost) / last_account_value`，把当天的手续费又加了回去，所以它是**毛收益**；
真正的净值在 `report["account"]`（现金+持仓市值，手续费已扣）。本策略日换手 33%、一年手续费
约 8 个百分点，毛和净差掉的就是整年赚头。

**发现过程不体面，如实写**：这不是我复查出来的，是做插件批次 F6 时让净值曲线自证
「起点=本金、终点=end_value」才暴露的（曲线终点 9,856 万 vs 读数 1.11 亿，对不上）。
所以这条属于「看到结果之后改口径」，按事后修正记录，不能算我预注册时判对了。

窗口 2023-01-03→2026-10-15（914 个交易日；末日 2026-10-16 按 §4 只出名单、不撮合）。
读数文件 `data/qlib/run_20261018-093511.json`（本金 1 亿）。

| 指标 | 净值读数（门槛认这个） | 毛利读数（原表贴的是它） | 口径 |
|---|---|---|---|
| 年化收益 | **+0.74%** | +9.23% | 243 交易日/年折算 |
| 对 `SH510300` 年化超额 | **−1.24pp** | +7.24pp | 策略年化 − 基准年化（基准 1.99%/年） |
| 累计收益 | **+2.82%**（1 亿 → 1.0282 亿） | +39.37% | 整段 914 天 |
| 最大回撤 | **−38.22%** | −34.03% | 账户净值 |
| 日胜率 | 48.47% | 49.45% | 914 天里赚 443 天 |
| 日均换手 | 33.32% | 同 | 日成本 3.33bp ⇒ 年化 8.09pp |
| 年度超额中位 | **+0.08pp** | +6.64pp | 4 个年度取中位 |

逐年（净值口径，pp = 对基准超额）：2023 **−5.51**、2024 **−13.00**、2025 **+9.35**、
2026（只 187 天）**+5.67**。

**裁决：门槛 B 判死。** 预注册的两条线——「扣成本后年化超额 > 0」实测 **−1.24pp**，不过；
「各年度中位数 > 0」实测 **+0.08pp**，且 4 个年度里 2 个为负，这个中位数没有区分度
（3 年 9 个月赚 2.8%，同期 510300 放着不动是 7.7%）。

门槛 A 依然成立（测试段 rank IC 0.0432、t 9.55，校正后 4.27；五分位单调），
所以完整结论是：**模型确实会排序，但一天换掉三分之一仓位的成本，比排序赚的钱多。**
下一步最该动的杠杆是把 `n_drop` 从 5 降到 2~3（压换手），或者换更长持有期的标签摊薄成本——

## 9. qlib 做成插件（批次 F3–F6，2026-10-18 预注册，门槛写在读数之前）

他的原话是「选股和回测是用插件完成的，既然是插件，替换不是很简单吗，qlib 也可以做成插件」。
先把两条链路**实际**的缝核对清楚（这一步推翻了一半的直觉）：

| 链路 | 真缝 | 换引擎要动什么 |
|---|---|---|
| 选股 | HTTP：8002 上三条固定路由，后端 `selection_service` 用 `settings.selection_plugin_base_url` 打过去 | **只改一个环境变量**（base_url 指到 8003），业务代码零改动 |
| 回测 | **没有 HTTP**。Celery 任务 `backtest.run`，worker 里 `from backtest_main import run_backtest` 直接 import 内核 | 换的是 worker 里的 **engine 分派**，不是 URL |

所以「qlib 做成插件」= 选股做成一个同契约的 HTTP 进程（`stock_selector_qlib/api.py`，8003），
回测做成一个同摘要形状的内核（`stock_selector_qlib/backtest.py`，由 `engine=qlib` 选中）。

### 三条硬约束（写代码之前就定下）

1. **服务进程不许驻 3.4 GB**。初版全跑峰值 3.39 GB 是因为要载 2016→2026 的训练面板；
   服务只做「短窗因子 + 落盘模型打分」，只读最近 130 个交易日。
2. **分数必须和 `scripts/qlib_run.py` 逐只相同**。关键在 `RobustZScoreNorm`：它的
   `mean/std` 是在**已加载的那段面板**上算的（`np.nanmedian`），服务进程自己重算就是另一个模型。
   所以训练侧 `--export-model` 把 booster + mean/std + 列序 + 票池落盘，服务侧只读、
   再原样复刻「÷std → clip(±3) → NaN 填 0」。
3. **qlib 不支持的参数必须报错，不许静默忽略**。TopkDropout 只按分数等权分仓，没有止损/止盈/
   持有天数/规则串；页面填了这些还照跑，读数就会冒充「设了止损的回测」。
   → `core/backtest_params.py` 的 `_check_engine` 直接拒。

## 10. 批次 G：把「还在推荐就拿着」写成可回测的规则（2026-10-18 预注册，读数在写完之后）

### 为什么要改（原话）

「一天不可能换掉三分之一的」「今天推荐 000001、明天也推荐 000001，那当没有持仓的时候，肯定用 000001 买入」。
§8/§9 的 `TopkDropout(topk=30, n_drop=5)` 每天**强制**换掉 5 只最低分 ⇒ 单边 16.7%、双边 33% 的日换手，
实测一年手续费 **8.09 个百分点**（`cost_annualized`）。这不是任何人的交易行为，
所以那个读数的**成本项是假的**——它可以判死 TopkDropout，但不能判死「低换手、还在榜就拿着」这条纪律。

### G0 规则口径（先定死，跑完不改）

- 买入候选：**当日分数前 50 名**（`entry_rank=50`）。
- 卖出：持仓只有**跌出前 100 名**（`exit_rank=100`）才卖；还在榜上就一直拿，不管它排第 3 还是第 90。
- 仓位：最多 10 只（`topk=10`），买入时等权（每只拿 1/10 的钱），榜上凑不满就留现金。
- **不做每日再平衡**：买完之后权重随价格漂移，不为「回到等权」而减仓。
  再平衡是他不会做的动作，硬塞进来等于凭空加换手。
- 补空位按分数从高到低，同一天多个空位按榜单顺序补。
- 改的**只有执行纪律**：模型、特征、标签、票池、成本、防前瞻红线全部不动。

### 11.3 页面表单接上引擎开关（#185）

- 单一事实来源：`form_spec()` 现在多返回 `engines` / `hold_rules` / `engine_excludes`，

- `_SELF_UNUSED_KEYS` 补进 `topk/n_drop/benchmark`：worker 是 `SimpleNamespace(**merged)` 整包喂内核

- 一个只有页面才会踩的坑：`n_drop` 是带缺省值的数字框，`hold_rule=band` 时后端会拒它

  dropout 藏 `entry_rank/exit_rank`，两个方向都收。
- 验证（浏览器实跑，不是只看代码）：`engine=qlib` 下 `strategy/rule_set_id/max_positions/
  position_cap_pct/target_amount/universe/max_hold_days/stop_loss_pct/take_profit_pct` 全部隐掉，

### 11.5 两个坑（下次别重新踩）

1. **nginx 热加载不能原地改一个已存在 `limit_req_zone` 的键**。改成 `$http_cf_connecting_ip` 之后
   reload 整次作废（`[emerg] limit_req "qlib" uses the "$X" key while previously it used the "$Y" key`），
   后面所有配置一条都不生效，而 `nginx -T` 读的是磁盘文件、看着像生效了 ⇒ 骗人。
   正确做法：**换一个 zone 名**（等于新建）。判断 reload 有没有落地要看 worker 进程年龄
   （`docker exec lexmath-nginx ps -eo pid,etime,args`），不是看 `-T`。
   另外 `SIGUSR1` 是重开日志，不是重载配置。
2. **8003 的地址写 `172.17.0.1` 不写 `localhost`**。它只绑 docker0 网关（供容器回连），
   没监听 127.0.0.1，写 localhost 会 `httpx.ConnectError`——实测过一次，17:30 选股会静默全挂。
   8002 是 `0.0.0.0`，所以这个坑只对 8003 成立。

## 14. 批次 K：持仓页的「当日榜内名次」（2026-10-18 14:05–14:25 落地）

用户拍板的 B 类第一优先：持仓页要能看到「我手里这只票今天在候选池里排第几」，

### 14.1 链路（三层，每层只做一件事）

```
8003  GET /api/selector/rank?codes=...          ← 名次唯一出处：当日全池打分排序
   └─ serving.ranks_by_code() → day_ranking()   ← 和 17:30 选股用的是同一份当日打分
8010  GET /api/v1/selection/rank?codes=...      ← 薄代理：拆码、去重、超限报错、把引擎形状翻给 App
   └─ selection_service.day_ranks()            ← 不重算、不兜底、不拿 select_results.rank_no 凑
App   持仓总览每一行「榜内名次 · …」+ 页头口径一句
   └─ logic/view.js::dayRankText()             ← 只翻译，不参与判断
```

`day_ranking()` 的缓存键是 `(model.run_id, 打分日)`，**topk 不在键里**：17:30 出名单和持仓页查名次
是同一次全池打分的两个视图，不是两趟计算。这样「第 8 名」和「进了前 30」永远不会互相打脸。

卖出线 `exit_rank` 从后端 `core/backtest_params.DEFAULTS["exit_rank"]`（=100）取，随接口下发给 App。
只有一个出处：band 纪律的回测参数改了，页面上「还在卖出线内 / 已跌出卖出线」的门槛跟着改，
不出现「回测按前 100 名卖、页面按另一个数提示」的两套口径。

### 14.2 实测延迟（决定了超时怎么设）

14:20 用真面板只读跑了一次（`--to-mongo` 没开，不落任何数据）：

| 场景 | 实测 | 口径 |
|---|---|---|
| 冷缓存第一次查名次 | **34.5 秒 / 299 只** | 其中 qlib 自己 `Loading data Done 32.614s`；即给整个票池补 130 天因子 + 打分 |
| 热缓存再查 | **0.03 秒** | 命中 `(run_id, date)` 缓存，只查表 |

### 14.3 「没有名次」的四种话术，一种都不许退化成假名次

名次这件事，"查不到"和"没上榜"在页面上必须能分开说——把前者写成后者，使用者会以为
自己手里那只票被模型看不上，从而做出卖出决定。四种情况：

1. **池外**（比如指数 ETF `510300`）：`in_pool=false` + `rank=null` +
   note「不在当前 300 只候选池里，模型没给这只打过分」。这是原话要求的那句。
2. **在池但当日无行情**（停牌/日线断档，如 601059）：`rank=null` +
   note「在 300 只候选池里，但当日没有可打分的行情（停牌或日线断档）」——
   它是有资格上榜的，只是今天算不出来。
3. **引擎根本不提供名次**（选指回自研内核、或插件未启用/mock）：整表 `supported=false` +
   message，页头说一句「当前选股引擎不提供榜内名次」，每行不再重复；
   8003 那边 404 就是这一类的成因，后端把 404 明确翻成这句话，而不是翻成空榜。
4. **查询失败**（5xx、数据盘没挂、代理报错）：后端 `BizError` → 页头「榜内名次没取到：<原因>」。
   **数据盘没挂时 qlib 是抛异常不是返回空表**，所以这条链路的失败形状是报错；
   如果哪天它变成"榜是空的"，那才是有人偷偷兜了底。

代码上的三个硬约束：`split_codes()` 超过 60 只直接 `BizError`（多出来的持仓绝不静默丢弃——
静默丢会看起来像"那几只没上榜"）；`rank_no`（选股批次内的序号）**不参与**名次计算；
`day_ranks()` 里没有任何 `or 0` / 默认名次之类的兜底。

持仓明细页（`pages/diag/detail.vue`）**不接这一行**：那是历史某一次的诊断结果，和"当日"名次放一起
会把两个日期混成一句误导的话，所以只在总览页展示。

### 16.3 本批新加的仪器守卫（有测试）

`holdout_ok(valid_beg, test_beg, train_end)`：**valid 与 test 的起点必须严格晚于训练段末尾**，否则——
`run_*.json` 里 `ic_valid/ic_test` 写 `None`、`holdout: false`，逐日 IC 表与预测表**不落盘**
（免得 `qlib_ic_pair.py` 把一份段内读数当成一条臂捡走），`--backtest` 直接 `SystemExit`。
理由：训练吃到末尾时 IC/五分档照样能算出一个像模像样的数，而那个数是模型背过的数据。
本批两臂都走"有留出"的分支，这条守卫是给下一批（训练再次吃到日历末尾时）留的。

另外两个开关：`--pool-end`（流动性窗右端与 `train_end` 解耦，捆在一起改就等于同时改两件事）；
`--fixed-trees`（恰好长 N 棵）。`--pool-file` 与 `--pool-end` 同时给会 `SystemExit`
（池已定死，`--pool-end` 只会被无声忽略）。

**`--fixed-trees` 的第一版实现是错的，冒烟跑抓出来了（读数之前，2026-10-18 17:00）**：
- 第一版按 qlib 文档传构造参数 `early_stopping_rounds=10**9, num_boost_round=N`，以为 patience 大到
  不可能触发就等于关早停。冒烟（`--smoke --fixed-trees 20 --export-model /tmp/…`）导出后
  `Booster.num_trees()` 只有 **12** 棵——`LGBModel.fit` **无条件**挂 `lgb.early_stopping`，而
  lightgbm≥4 在训练收尾时把 booster **裁到 best_iteration**，patience 多大都照裁。
- 改成自己调 `lgb.train`（不挂早停回调）后又读到 **600** 棵：`LGBModel(**kwargs)` 把 kwargs 原样塞进
  `self.params`，而 `n_estimators` 在 lightgbm 的别名表里映射到 `num_iterations`，**盖掉**了
  `num_boost_round`。摘掉 `n_estimators/num_boost_round/num_iterations` 三个键后实测 20/20。
- 现在这段自带硬校验：训完 `num_trees() != N` 直接 `SystemExit`（"容量没钉住，两臂不可比"），
  不留给读数阶段发现。冒烟产物（`run_smoke*.json` / `ic_daily_smoke*.parquet` /
  `pred_smoke*.parquet` / `instruments/smoke*.txt`）已全部删除。

顺带一条对**既有读数**的解释：`n_estimators=600` 一直在 params 里，所以 §15 那两臂的早停上限是
600 轮而不是 qlib 默认的 1000 轮；实测棵数 131/48 都远小于 600 ⇒ 那批读数不受影响。

### 17.2 三个必须先讲清的事实（写在读数之前）

1. **模型只在流动票上训练过**。RobustZScoreNorm 的 mean/std 是训练池那 300 只拟合的，
   给池外票打分是**外推**。外推不是错，但没量过就不能当准。
2. **名次含义会变**。`universe` 从 298 变成约 5,000，「排第 5」从前 1.7% 变成前 0.1%。
   band 纪律（G1/G4）的 `entry_rank/exit_rank` 是**绝对名次**，在新口径下等于把门槛抬高约 16.7 倍，
   所以 **G4 那批回测读数在放开池之后不作数**，要重跑才算，不能拿旧数说明新策略好不好。
3. **放开池必须同时放开增量链**。16:00 的 `qlib_update_bin.py` 一直只补票池那 301 只（`--scope pool`），
   名单放开后如果增量链还跟着旧池走，17:30 就会给池外票打**上一个交易日**的因子，而且分数看起来完全正常

   不是后续优化。

口径逐条交代：
- A 组 = 当天在旧 300 只训练池里的名字，B 组 = 当天在全市场名单但不在旧池的。两组用的是同一个模型、
  同一天、同一套 5 日标签（`Ref($close,-5)/Ref($close,-1)-1`），所以差值是按天配对的。
- **5 日标签相邻两天用的是几乎同一批收益**，配对 t 要 ÷√5（§11 那条口径）。÷√5 后 −0.88 ⇒
  用大白话讲：**「池外比池内差」这件事在统计上分不出真假**，那点差距和随机波动一个量级。
- 采信窗口只有 67 个交易日 ≈ **13 个互不重叠的 5 日窗口**，样本量本身就小；线要求 B 组日数 ≥ 30，67 天够。
- `--from 2026-06-30` 含 train_end **当天**（那天当特征日可能仍落在训练段里），只 1 天，不改变结论。
- 剔 ST 那条用的是**今天（10-18）抓的现名清单**回头剔整个窗口，属于敏感性检查，不是可实盘的历史判据。

### 17.6 G-N3 开跑前的两条仪器事实 + 一次判据修正（2026-10-18 18:52 写；先于任何 G-N3 读数）

冒烟测试（700 只 × 120 个交易日，`--out /tmp/gn3_smoke2`）暴露了三件事，都必须写在读数之前。

1. **qlib 的因子值与请求窗口无关**。同一批票，窗口 `2026-04-01→2026-10-16` 与 `2024-01-01→2026-10-16`
   在**共同首日** 2026-04-01 上的 158 个因子逐位相同（5 只票最大差都是 `0.000e+00`，NaN 计数都是 0/158）。
   ⇒ qlib 是先在整条日历上算表达式、再切片，**重放历史不需要留 warmup 前缀**。
   顺带记下：`serving.WARMUP_DAYS = 130` 对「最后一行的因子正确」并不是必需的。
   **这行不动**（改了会连带影响缓存与耗时口径），只是别再把它当正确性前提。
2. **`D.features` 的索引层级和 Alpha158 handler 是反的**。handler 给 `(datetime, instrument)`，
   `D.features` 给 `(instrument, datetime)`；不对齐层级就 `reindex` 会**静默全 NaN、一行都不报错**。
   我第一版就是这么写的，差点带着「标签全空 ⇒ 一天都聚不出 IC」当结论交回去。脚本里现在先
   `reorder_levels(["datetime","instrument"])` 再 reindex，并加了一道硬检查：
   **对上的标签比例 < 50% 直接抛错**，因为那种缺口只可能是 join 错了，不可能是行情缺。
3. **判据要按样本外窗口判，不然量的不是外推**。预注册写的重放区间是 2023-01-01→2026-10-16，
   但线上模型 `live2026jun` 的 `train_end` 是 **2026-06-30**（`data/qlib/model/meta.json`）——
   这段区间里 A 组（训练池内的票）是**被模型训练过的票**，B 组不是。所以拿整段的 A/B 差去判
   「外推可不可信」，量到的是**样本内记忆 vs 样本外**，不是「池内 vs 池外」。冒烟实测就是这个样子：
   700 只 × 120 天（2023 上半年）里 A 组均值 IC **+0.2111**、B 组 **+0.0454**，比值 0.215。
   `+0.21` 这个量级的日频 IC 不是真实预测力，是 141 棵树在自己训练票上的回头率。
   - **修正**：重照样跑满 2023-01-03→2026-10-08（909 个交易日，一条不落），但**采信线只在
     `train_end` 之后的窗口上判**（`--aggregate --from 2026-06-30`），即 2026-07-01→2026-10-08 这一段
     ——那里 A、B 两组都是未来数据，唯一差别就剩「在不在训练池」，这才是这批要问的事。
     这段 60 多个交易日，仍满足「B 组日数 ≥ 30」。
   - 0.700 这条线**不动**，只是换了判它的窗口；整段（含样本内）的读数也照样出、照样落档，
     标注清楚「含样本内，不能当外推证据」。
   - 第二道修正在冒烟里已经看到必要：**B 组天然比 A 组更薄**。按当日 20 日均成交额分三档后，
     冒烟段 A 组的名字**全部落在最流动的 T1 档**（池本来就是流动性前 300 选的），
     而 A-T1 的 IC +0.2170 vs B-T1 +0.0296。所以「同档比」是必须报的，
     不然池的效应和流动性的效应分不清。

3. 与 close≥MA20 相比，MA5>MA10 温和得多（总收益 +12.6% vs −19.8%），因为它允许"刚拐头"的票进来；
   但两者都输给 A1，且都主要输在 2023/2025 两个反弹年。
4. 覆盖率不是解释项：前 50 名平均仍有 25.1 只可买，H1 不是"空仓版 A1"，而是系统性换了一批票——
   与 G1 一样，换掉的恰是分数最高的那批超跌反弹候选。
5. 本批再次量到"模型已经学过这个条件"：MA5/MA10 本来就是 Alpha158 的特征，树模型可以直接实现
   `MA5>MA10`；策略层硬过滤等于覆盖模型的条件期望，负向是预期内的结果。

**本批结论**：`MA5>MA10` 入场闸门在这条链路 + 这个窗口上**不成立**。按 §19.3 第 3 条，
**这个窗口上的入场条件实验到此收口**：不再在同一窗口追加第 5 个条件（含 T+3、T+8 之类的变体）。
要改善"排名第一还在下跌"的观感，改模型/标签层（批次 P：T+10 / T+20，见 §20）或用"展示层提示、
不过滤"对齐；组合层不再调"趋势条件"这一个旋钮。

**产物**：曲线 `data/qlib/batch_O2_curves.parquet`（914 天 × A1/H1/H2/bench）；日志
`logs/qlib_batchO2_full.log`（canonical，含配对/子窗/裁决）；首跑日志 `logs/qlib_batchO2_full.run1.log`
（报告段缺失的留痕：`pairs` 里臂名写死 G1/G2/E1；配对值已由落盘曲线复算、与 canonical 打印逐位一致。
脚本已修：pairs 自适应、O2 裁决分支、曲线按批次落名）。O 批曲线在首跑时被同名覆盖，已用同脚本重跑
A1/G1/G2/E1 重建 `data/qlib/batch_O_curves.parquet`（日志 `logs/qlib_batchO_rebuild.log`），
读数与 §18.5 逐项一致；`stock_selector_qlib/backtest.py` 的 `entry_gate/scan_all` 仍默认关闭（线上未动）。

## 20. 批次 P：标签周期 A/B（T+1→T+10 / T+1→T+20）（2026-10-19 08:12 预注册；写在任何本批读数之前）

### 20.1 由来与前提

- §18.5 / §19.5：入场闸门族（close≥MA20、MA20 斜率、MA5>MA10，含全榜扫描）在这个窗口上全部
  不成立/未证明，且**这个窗口上的入场条件实验已经收口**。
- 归因（§18.1 的事后分析）：排名第一的趋势向下不是 bug，是 5 日标签
  （`Ref($close,-5)/Ref($close,-1)-1`）在训练窗里学到的短期反转倾斜；MA5/MA10/MA20 本来就在
  Alpha158 里，模型自己会学，组合层硬过滤=覆盖模型的条件期望。
- 用户决定（2026-10-19）：「如果还是不行，就转到标签/滚动重训」。
- 本批**只回答一件事**：在其余一切逐字相同的前提下，把标签拉长到 10 / 20 天，band 纪律的扣成本
  净收益会变好还是变差、值不值得进独立样本复验。**不回答**"能不能上线"，**不回答**重训/滚动
  （那是下一批）。

### 20.2 口径（写死）

| 项 | 值 | 为什么 |
|---|---|---|
| 训练窗 | 2016-01-01 → 2021-12-31 | 与研究臂逐字相同：本批只隔离"标签"这一维 |
| 验证段 | 2022-01-01 → 2022-12-31 | 同上；**不参与选择**（固定树数绕过早停） |
| 回测窗 | 2023-01-03 → 2026-10-15（914 天） | 与 §18/§19 相同，A1 可直接对照 |
| 票池 | `data/qlib/model_research_trainend2021/pool.txt` 冻结 300 只 | 与研究臂逐字相同 |
| 特征/预处理 | Alpha158，RobustZScoreNorm 拟合到 2021-12-31 | 逐字相同 |
| 标签 | P5：`Ref($close,-5)/Ref($close,-1)-1`（对照）<br>P10：`Ref($close,-10)/Ref($close,-1)-1`<br>P20：`Ref($close,-20)/Ref($close,-1)-1` | **唯一变量** |
| 树数 | 61（研究臂实测 `num_trees()=61`） | 三臂容量相同；否则树数是自由变量 |
| seed | 不设（与研究臂同口径） | 同上 |
| 其余 LightGBM 参数 | `scripts/qlib_run.py` 的 LGBModel 配置逐字不改 | 同上 |
| 交易纪律 | §10 A1 band：进 50 / 出 100 / 持 10，成本与撮合逐字相同 | 隔离标签；**不为长标签重调持有期** |
| 基准 | SH510300 | 同上 |

两条写在前面的代价/限制：

1. **长标签 + 原持有纪律可能低估 P10/P20**：band 的进/出/持有参数是按 5 日标签的持有期挑的
   （§10 写过 `exit_rank=100` 对应平均持有 ≈5 天再留缓冲）。本批故意不重调——否则"标签"和
   "持有期"两个变量会混在一起。P10/P20 若点估计为正但没过线，**不能**靠"再调一下 band"来救；
   要调是下一批，且必须换独立样本。
2. **标签右端跨过训练段末尾**：T+1→T+H 的样本在 2021-12 月末需要 2022-01 的价格才能算标签
   （研究臂的 5 日标签同样如此，最多 5 天；本批最多 20 天）。因为 valid 不参与选择（固定树数），
   这不构成对 test（2023 起）的泄漏；写在这里是为了不让它以后被当成新发现。

### 20.3 仪器门（任何一条不过，本批读数全部作废、只当管道测试）

1. **P5 必须复现研究臂**：P5 的分数面板与 `data/qlib/model_research_trainend2021` 在同一窗口
   逐点比较，最大绝对差 ≤1e-9、对齐率 ≥99.9%。
2. **P5 的 A1 band 必须复现 §G4**：总收益/年化/最大回撤/单边换手差 ≤0.1pp；净值曲线 vs
   `data/qlib/batch_G_curves.parquet["A1"]` ≤1e-6、914/914 天对齐。
3. 每臂训练后 `num_trees()==61`（`qlib_run.py` 自带校验，不通过直接退出）。
4. 三臂回测必须走同一 `stock_selector_qlib.backtest` 引擎、同一窗口/成本/基准
   （`scripts/qlib_label_horizon_ab.py`）；头部趋势诊断只做描述，不参与裁决。

### 20.4 裁决线（写死）

- 主臂：**P20**（最长周期，最接近"趋势/持有"假设的检验）；P10 是记录臂。
- 主判据（P20 − P5，配对日净差，扣成本净值）必须**同时**满足：
  a. 点估计 > 0；
  b. 整窗 t **÷√20** ≥ 2（20 日重叠标签；P10 的记录值用 ÷√10）；
  c. 两个子窗（2023-01-03→2024-12-31 / 2025-01-01→2026-10-15）方向都为正；
  d. 点估计层面年化净收益 > P5；
  e. 一致性：P10 − P5 点估计 > 0（不要求过 t；方向相反视为不稳定）。
- **即使五条全过，也只判"进入独立样本复验"**（换窗口 / 换票池抽样 / 滚动重训臂），不判有效、
  不许直接上线——这是同一窗口上的标签族比较，单窗口证据的上限就在这里。
- 任一条不过 ⇒ 判"不成立/未证明"，**标签周期这一维在这个窗口上收口**：不许再在同一窗口追加
  T+30/T+60 等变体，也不许靠调 band 参数救。
- 记录项（不设线）：P10 全部读数；三臂的年化/回撤/换手/成本/平均持有/分年；**头部趋势诊断**
  （前 10 名的 close≥MA20 比例、10 日收益中位数、20 日动量中位数、整池分数与 20 日动量
  rank corr）——这是用户最初问题的直接观测量，但它是描述项，不参与裁决；峰值内存。
- 对照关系：P5 若复现研究臂，则 P5 的 A1 band 读数就是 §G4 的 A1
  （+29.38% / +7.09% / −22.36% / 14.28%），两套数字互为仪器证据。

### 20.5 跑法（串行，单臂峰值 ~2.9 GB；三臂训练约 15 分钟）

```bash
# 三臂训练（--label-horizon 默认 5，历史行为不变；--skip-selection 防覆盖 10-16 的审计名单）
for H in 5 10 20; do
  env -u QLIB_MODEL_DIR /usr/bin/python3 -u scripts/qlib_run.py \
    --pool-file data/qlib/model_research_trainend2021/pool.txt \
    --inst-name labP$H --run-id batchP_lab$H --fixed-trees 61 \
    --label-horizon $H --backtest --skip-selection \
    --export-model data/qlib/model_batchP_lab$H
done

# 同一 band 纪律下的回测与读数（主窗口）
env -u QLIB_MODEL_DIR /usr/bin/python3 -u scripts/qlib_label_horizon_ab.py --arms P5,P10,P20
```

（脚本 `scripts/qlib_run.py` 只新增 `--label-horizon` / `--skip-selection` 两个参数，默认值与
历史口径一致；`scripts/qlib_label_horizon_ab.py` 为新文件，只读三份研究产物。）
