# 1. 文档说明

## 1.1 目的

本文档定义"智能选股助手 v1.0"的系统级功能性需求与 DFX 约束，作为总体设计、概要设计与测试用例设计的输入。

**本次迭代范围：** 在既有 `stock_selector` 选股插件（独立 HTTP 服务，只查行情给信号）与 `stock_selector_api`（FastAPI 通用后端模板，含认证/通知/健康检查）之上，新增一套 UniApp 客户端（手机 App + PC 浏览器 H5）与后端选股/通知/消息/版本/持仓诊断模块，实现：① 选股信号获取与快照落库 + 历史按自然日回看；② 定时选股由外部调度服务驱动并自动通知；③ 通知渠道/订阅策略可视化配置；④ 站内信 + WebSocket 实时消息补收；⑤ 多账号登录与数据按用户隔离；⑥ App 整包版本管理；⑦ 持仓诊断闭环（持仓录入/导入 → 定时把当前持仓发插件统一判定买卖·加仓 → 收益快照落库回看 + 属主通知）。

**明确不包含：**
- 后端不内嵌/不重写任何选股计算（仅代理查询插件信号）
- 后端不内嵌任何持仓买卖判定与收益计算（判定收敛到插件 `POST /api/portfolio/analyze`，收益以插件返回为准存储）
- 定时任务不进 FastAPI（由外部独立调度服务发起）
- UniPush/个推厂商离线推送通道（App 被杀后不承诺离线送达）
- 个股 K 线图、自选股/关注列表
- UniApp 内用户/角色/权限/RBAC 管理页、注册与密码找回（账号由后端 sys_users 供给）
- iOS 原生分发（TestFlight/App Store）与 wgt 热更新（本期仅 Android 整包 APK + H5 刷新提示）
- 出海/国际化、NFV/XAAS 类需求（不适用）
- **OneTrack 主线合一**：不适用（个人自用工具，无企业需求管理平台接入）
- 数据自动清理（本期数据量受控，不做清理任务）

## 1.2 定义和缩写

| 缩写/术语 | 全称/定义 | 备注 |
|---|---|---|
| SelectRun | 一次选股执行快照（select_runs 头表）：owner_type(user/system)/owner_id/trigger_type(manual/scheduled)/strategies/status(running/success/failed)/result_count/started_at/finished_at/duration_ms/error | 上游 TR1 §词汇表 |
| SelectResult | 一条命中信号记录（select_results 明细）：run_id/code/name/signal/reason/extra(JSON)，唯一约束(run_id, code, signal) | 同上 |
| Holding | 用户当前持仓记录（holdings）：id/user_id/code/name/quantity/cost_price/enabled，按用户隔离，作为诊断输入 | TR1 §词汇表 |
| DiagRun | 一次定时持仓诊断运行（portfolio_diag_runs 头表）：id/user_id/trigger_type/status/holding_count/action_count/total_market_value/total_pnl/started_at/finished_at/duration_ms/error | 同上 |
| DiagResult | 单只持仓诊断结果（portfolio_diag_results 明细）：run_id/code/name/action(buy/sell/add/hold)/reason/收益快照/extra，唯一约束(run_id, code) | 同上 |
| 收益快照 | 诊断时刻插件返回的 last_price/market_value/pnl/pnl_pct，后端仅存储透传不重算 | 同上 |
| Channel | 通知渠道：企微/钉钉/飞书/邮箱四类 webhook 配置，按用户隔离 | 同上 |
| Policy | 订阅策略：事件类型 + 渠道类型列表 + 节流间隔，全局共享一套 | 同上 |
| Inbox | 站内信：系统事件消息记录（inbox_messages），按用户隔离 | 同上 |
| 外部调度服务 | 调用选股插件并导入后端的独立定时服务（cron/脚本），不进 FastAPI | 同上 |
| manual 运行 | trigger_type=manual：用户在 App 手动触发的选股运行，归属用户（owner_type=user） | 多用户语义 |
| system 运行 | 外部调度导入产生的选股运行（owner_type=system），对所有用户可见 | 多用户语义 |
| latest_id | 客户端本地已读到的站内信最大 id，断线重连后按 since=latest_id 补齐 | WebSocket 补偿 |
| version_code | App 版本号数值（用于大小比较）；version_name 为展示文案，不参与比较 | 版本管理 |
| force | 强制更新标记：force=1 时更新弹窗不可跳过 | 版本管理 |

> 本版本术语与 TR1 保持一致，无术语含义变更；地址/接口名变更属设计阶段决策，不影响术语定义。

## 1.4 版本需求范围

### 1.4.1 本版本包含

| 功能模块 | 实现范围说明 | 完成度目标 |
|---|---|---|
| 选股 | 策略清单展示、立即选股（异步代理插件，单并发）、结果快照落库、自然日历史浏览、外部调度导入（幂等+系统级） | 完整功能 |
| 持仓诊断 | 持仓录入/导入（手动+CSV，按用户隔离）、定时诊断（外部调度触发，插件统一判定买卖/加仓+收益快照）、诊断结果双表快照落库与按日回看、属主双路通知 | 完整功能 |
| 通知 | 四类 webhook 渠道按用户管理 + 测试发送、全局订阅策略、事件双路推送（webhook+站内信）、WebSocket 实时消息 + 断线补齐、安卓本地通知 | 完整功能 |
| 客户端基座 | 多账号登录（验证码）、4 Tab 响应式外壳（手机底部 Tab / PC 侧栏）、账号与设置、App 整包版本管理（可选/强制） | 完整功能 |
| 多用户 | 数据按用户隔离（含持仓/诊断）、系统级运行全员可见、越权防护、写操作审计 | 主流场景 |

### 1.4.2 本版本明确不包含

- UniPush/个推厂商离线推送：App 被杀后不保证送达（相关离线补偿由站内信 since 补齐覆盖）
- 个股 K 线图、自选股/关注列表：个人工具范围外，无规划版本
- 持仓诊断的手动触发：诊断仅由外部调度定时发起，本期不提供 App 手动触发入口（避免与选股手动流程混淆）
- 盘中实时收益刷新：收益为诊断时刻快照，不提供实时行情联动
- UniApp 内用户/角色/权限/RBAC 管理页、注册/密码找回：账号由后端 sys_users 供给，无规划版本
- iOS 原生分发（TestFlight/App Store）与 wgt 热更新：iOS 渠道依赖企业签名，留后续版本评估
- 出海/国际化、NFV/XAAS、OneTrack 主线合一：不适用（个人自用工具）
- 数据自动清理：不适用

### 1.4.3 后续版本规划（可选）

- v+1：iOS 分发渠道、复杂通知路由（按股票/条件）、选股结果图表化、持仓诊断手动触发与盘中收益实时刷新
- v+2：数据保留与归档策略、更多事件类型、持仓组合统计（行业/仓位占比）
