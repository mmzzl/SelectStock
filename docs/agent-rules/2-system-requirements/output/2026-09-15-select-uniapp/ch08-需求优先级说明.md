# 8. 需求优先级说明

## 8.1 优先级定义

| 优先级 | 定义 | 时间要求 | 验收/发布要求 |
|---|---|---|---|
| P0 | 本产品核心价值闭环与必备基座，缺则不可用 | 必须在 v1.0 发布前完成并被验收 | 作为交付门禁，P0 未过不可发布 |
| P1 | 增强性/治理性需求，缺则功能可用但体验/可维护性受损 | 允许延迟到 v1.x 补发；本期完成优先保障 P0 | 随迭代交付，不阻塞 v1.0 主路径 |

## 8.2 优先级分配

| 优先级 | 需求清单 | 数量 |
|---|---|---|
| P0 | REQ-001~REQ-015 | 15 |
| P1 | REQ-016（任务治理）、REQ-017（写操作审计） | 2 |

## 8.3 裁剪与取舍说明

- P1 两项为治理增强：REQ-016 兜底 P0 长任务、REQ-017 留痕写操作；若 v1.0 周期紧张，P0 十五项全部通过后可先行发布，P1 补齐后升级。
- 单并发、超时、失败通知已内嵌在 REQ-016（P1）；REQ-002/003 的 GWT 中的超时/失败行为依赖 REQ-016，注意实现时叠加（REQ-016 作为全量治理层）。

## 8.4 其他需求管理规则

- 变更：新增/调整 REQ 须更新 ch03 对应编号、ch05 测试点、ch07 跟踪表，并按 §9 修订记录登记。
- 编号唯一性：REQ-XXX 全局唯一，禁止复用。
- 非功能性指标（ch04）随需求变更同频更新，禁止只改功能不改 DFX。
