**[ISSUE-001]** — REQ-28（§2 场景覆盖充分性）
- 文档: 2026-09-15-select-uniapp 文档集
- 位置: ch02 §2.1~§2.5 全部 5 个场景
- 规则: REQ-28 — 每个场景须含异常分支要素
- 引用原文: 场景表列仅为"场景描述/用户角色/使用方式/原型依据/操作流程/期望目标/业务价值"（§2.1~§2.5 结构相同）
- 问题描述: 5 个应用场景均无独立"异常分支"字段；异常处理仅内嵌于操作流程/期望目标（如 §2.1"离线由站内信补齐"、§2.4"MD5 不一致不安装"、§2.5"越权请求返回无权限语义"）。内容存在但未按要素显式化。
- 严重级别: Warning | 扣分: -8（需求完整性）
- 修改建议: 每个场景增加"异常分支"行（触发条件+降级行为），或引用对应 REQ 的 GWT 异常场景章节号，保持场景要素完整。

**[ISSUE-002]** — REQ-26（§4.8/§4.9 日志保留时长）
- 位置: ch04 §4.9 LOG-05
- 规则: REQ-26 — 日志与可观测性须覆盖操作范围/错误告警/保留时长，不得仅写"不涉及"或"参见平台"
- 引用原文: "审计记录保留：跟随日志保留策略，不阻塞业务"
- 问题描述: 操作日志范围（LOG-03）与错误/告警支撑（LOG-04 健康检查、REQ-008 WARN 日志）已覆盖；但日志/审计的**保留时长未量化**，仅写"跟随日志保留策略"，实质引用部署既有策略。
- 严重级别: Warning | 扣分: -8（技术可行性）
- 修改建议: 在 LOG-05 补充具体保留期限（如"日志滚动保留 ≥90 天，审计记录保留 ≥180 天，容量上限可配置"）。

**[ISSUE-003]** — REQ-18（§5.4 安全测试点对齐）
- 位置: ch05 §5.4 ST-01~05
- 规则: REQ-18 — 安全测试点须覆盖 §4 安全要求场景
- 引用原文: ST-01~05 关联项（SEC-01/03/04/02/05）
- 问题描述: ST 矩阵未显式覆盖 SEC-06（部署密钥 .env 隔离）与 SEC-07（认证令牌不入日志）；SEC-07 的"失效/过期"行为由 TC-10/TC-11 兜底，"令牌不入日志"维度无测试点。
- 严重级别: Warning | 扣分: -8（可测试性）
- 修改建议: 补充 ST-06（部署密钥环境变量注入、日志扫描无密钥明文）、ST-07（请求/响应/错误日志断言不含 token）。

**[ISSUE-004]** — REQ-35 / SUP-05（测试工具需求）
- 位置: ch04 §4.7 可测试性
- 规则: REQ-35 — 测试工具表格至少覆盖单元测试与接口测试两行，且"与系统的集成方式"列不得为空
