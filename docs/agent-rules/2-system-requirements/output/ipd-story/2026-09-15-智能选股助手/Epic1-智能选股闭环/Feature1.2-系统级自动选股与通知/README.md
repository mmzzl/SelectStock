## 【Feature】Feature1.2-系统级自动选股与通知

【关联关键价值点】⭐

支撑 Epic1"定时自动选股 + 信号主动送达"价值：外部调度每日自动导入选股结果为 system 运行，事件触发即多通道通知，在线实时到达、离线站内信补齐，彻底替代 SSH/命令行手动执行（对应 ch02 场景1）。

【特性需求分类】⭐

基本可用——"收盘自动选股 + 主动通知"是本产品替换每日手工操作的核心价值，缺失则产品名不副实。

【功能级 Playbook】⭐

1、定时选股场景：外部调度 15:05 调用插件 → 调用 `POST /select/import` 导入信号（幂等）→ 落库为 system 运行（全员可见）→ 触发 select_completed → 按订阅策略分发外部渠道 + 站内信必写 + 在线 WebSocket 推送。
2、消息查看场景：打开消息 Tab → 查看站内信列表/未读徽标 → 点开详情 → 标记已读。
3、实时触达场景：在线收到信号弹 Android 通知栏（本地通知）可点击跳转；断线重连按 since=latest_id 补齐缺口。

【场景建模】🔲

不涉及（场景已在 ch02 场景1 完整描述，层级简单无需三级分解）。

【关键交互说明】🔲

- 消息 Tab 徽标展示未读数（100+ 显示"99+"），读取后减少。
- 离线期间消息由站内信持久化补齐，回前台重连后弹未读通知。

【特性验收条件】⭐

1. 重复导入同一批数据不重复建 run（REL-06 幂等）。
2. 事件触发即双路分发：外部渠道 by 策略 + 站内信必写；webhook 失败不阻塞（REQ-008 验收）。
3. 在线客户端事件→收到 ≤5s（PERF-05）；站内信落库 ≤1s（PERF-07）；导入吞吐 500 条 ≤5s（PERF-06）。
4. 断线重连按 since 补齐，消息不丢（REL-04）。
5. 站内信仅本人可见、未读数/已读状态正确（REQ-009 验收）。

【非功能需求约束 DFX】⭐

QS-004 要求 DFX 需求基线全量落地，不满足项有 Story 跟踪。

- 性能：在线推送 ≤5s（PERF-05，Story1.2.4）；站内信落库 ≤1s（PERF-07，Story1.2.2）；导入吞吐 500 条 ≤5s（PERF-06，Story1.2.1）；站内信查询 p95 ≤1s（PERF-02，Story1.2.3）
- 可靠性：断线由站内信持久化补齐（REL-04，Story1.2.4）；幂等导入（REL-06，Story1.2.1）
- 安全性：站内信/WS 按 user_id 路由与隔离（SEC-01，Story1.2.3/1.2.4）；导入鉴权复用统一认证（SEC-02，Story1.2.1）；认证令牌不入日志（SEC-07）
- 可测试性：消息数据可构造、WebSocket 推送可观测（TES-03/04，Story1.2.3/1.2.4）
- 可运维性：健康检查 `GET /api/health` 供外部调度探测（LOG-04）；操作留痕可追溯（LOG-03）
- 其他：双路互备无单点；非 XAAS，客户成功维度不涉及（QS-008 裁剪）
