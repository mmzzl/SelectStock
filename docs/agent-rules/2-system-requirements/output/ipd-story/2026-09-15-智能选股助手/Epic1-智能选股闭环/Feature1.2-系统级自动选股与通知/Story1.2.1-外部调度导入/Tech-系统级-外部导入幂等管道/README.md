# Tech-系统级-外部导入幂等管道

1、【技术故事】 - TL & 模块负责人

支撑 Story1.2.1（REQ-005）的导入链路：外部调度调用 `POST /select/import`（幂等键 + 信号集）→ 服务端按幂等键校验 → 创建 system 运行并落库 → 触发 select_completed 全员通知（REQ-008）。导入不做选股计算、不内嵌调度。

关联的系统需求编号：REQ-005；依赖 REQ-003（落库）、REQ-008（通知）、REQ-011（认证）。

2、【A/C验收条件】 - TL & 模块负责人

2.1 功能性验收条件

1、业务规则、边界：
- 单一接口 `POST /select/import`；入参含幂等键 K 与信号集；鉴权复用统一认证。
- 幂等：相同 K 重复导入不重复建 run，返回已有运行 id。
- 格式非法（字段缺失/类型错误）返回 4xx，不产生任何运行。
- 产生 owner_type=system 运行，全员可见；空信号导入保留 result_count=0 的运行留痕。

2、系统功能约束：
- 导入接口不做选股计算（仅承接外部信号与落库）；定时任务不进 FastAPI（外部调度驱动，ch06 §6.1）。

3、实例化场景（正常场景和异常场景）：
- 正常：带幂等键 K 与信号集 → 建 system 运行落库、全员可见、触发 select_completed；响应含运行 id/状态/命中数。
- 异常：相同 K 重复调用 → 不重复建 run 返回已有运行；无凭据调用 → 401；普通用户构造 owner_type=system → 以调用者凭据判定不信任开放字段。

2.2 非功能性验收条件

1）性能分析：导入吞吐 500 条信号 ≤5s（PERF-06）。
2）可靠性：幂等、失败可重试不造成脏数据（REL-06）。
3）可维护性：导入成功/失败/幂等命中均留痕（LOG-03）；调度监控由外部调度负责。
4）开放性：`POST /select/import` 为外部调度单一入口（OPN-02）；接口入 OpenAPI 文档（OPN-01）。
5）安全性：鉴权复用统一认证（SEC-02）；owner 服务端判定防伪装（SEC-01）；token 不写日志（SEC-07）。
6）其他：可测试性——固定幂等键连续调用 3 次断言 select_runs 中仅 1 条运行、明细不重复（TES-03）。

3、【依赖与风险】 - TL & 模块负责人

1、需求关联性，内部功能依赖，外部跨团队协作：依赖 REQ-003/008/011；外部调度调用约定（幂等键）需确认。
2、技术风险、测试风险：外部调度失联/重复（中）→幂等 + 失败可重试；幂等键语义需与调度方对齐。
