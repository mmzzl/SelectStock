### 【Story】Story1.2.3-站内信 🔴

> 来源：REQ-009（P0）

【用户故事】⭐

作为个人投资者（使用者本人），我想要在消息 Tab 查看本人站内信（列表/未读标记/已读），以便错过的通知可回溯查看。

【场景说明】⭐

针对消息中心场景：select_completed/select_failed 等事件写入 inbox_messages，消息 Tab 展示列表 + 未读徽标 + 已读操作；仅本人消息可见。
**痛点背景**：离线/不看第三方渠道时消息丢失；诉求=站内信持久化、未读可见、可标记已读。
- 来源：REQ-009（关联 ch02 场景1）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- inbox_messages：id/user_id/type/run_id?/title/content/read_status/created_at。
- `GET /api/v1/messages`：按当前用户过滤 + 分页 + 返回未读数。
- `PUT /api/v1/messages/{id}/read`：标记已读。
- 事件覆盖：select_completed/select_failed（后续可扩展）。
- 未读数在 Tab 徽标展示（100+ 显示"99+"），读取后清零/减少。

2、实例化场景描述：

   正常场景：列表与未读
   Given（前提条件）：用户有 3 条消息，2 条未读
   When（行为）：打开消息 Tab
   Then（结果）：列表倒序展示 3 条，徽标/未读数=2

   正常场景：标记已读
   Given（前提条件）：选中 1 条未读消息
   When（行为）：标记已读
   Then（结果）：read_status=read，未读数减 1；全部读完徽标消失

   异常场景：越权标记
   Given（前提条件）：用户 B 携带用户 A 的消息 id
   When（行为）：标记已读
   Then（结果）：拒绝，返回无权限语义

   异常场景：消息不存在
   Given（前提条件）：id 不存在
   When（行为）：标记/查看
   Then（结果）：404，明确提示"消息不存在"

   安全场景：隔离
   Given（前提条件）：A、B 各自有消息
   When（行为）：各自查询
   Then（结果）：互不可见对方消息；非属主请求不返回字段（404/无权限）

   边界场景：空态 / 大分页
   Given（前提条件）：新账号无消息 或 消息 >100 条
   When（行为）：打开/翻页
   Then（结果）：空态文案"暂无消息"无报错；分页正确无漏无重，p95 ≤1s

【操作步骤】⭐

1. 打开消息 Tab（含未读徽标）。
2. 查看消息列表（时间倒序，未读高亮）。
3. 点开详情查看 title/content/时间。
4. 标记已读 → 未读数减少。

【期望效果】⭐

站内信仅本人可见、未读数/已读状态正确、标记已读生效、列表查询 p95 ≤1s（PERF-02）。

【需求规格约束】🔲

消息 Tab 交互稿（待交互设计阶段产出）；徽标 100+ 显示"99+"。

二、非功能性验收条件 ⭐

【产品需求】

- 性能：列表查询 p95 ≤1s（PERF-02）。
- 可靠性：站内信为同步源，离线/断线由站内信补齐（REQ-010 依赖）。
- 可测试性：站内信数据可经接口/事件可靠构造，断言列表/未读/已读状态（TES-03）。

【安全需求】⭐ 必填（QS-007）

- 仅本人可见（user_id 强过滤，服务端强制）（SEC-01）。
- 越权操作返回无权限语义，不泄露资源存在性。
- 消息字段（run_id/type）不返回给非属主。
- token 不写日志（SEC-07）。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
