### 【Story】Story1.2.4-WebSocket实时消息与断线补齐 🔴

> 来源：REQ-010（P0）

【用户故事】⭐

作为个人投资者（使用者本人），我想要在线时新消息实时到达、收到信号弹安卓通知栏、断线重连后消息按 since 补齐不丢失，以便实时掌握选股信号。

【场景说明】⭐

针对实时触达与离线补齐场景：`/ws/notify` 按 user_id 路由实时推送；断线期间消息以站内信持久化，重连后按 since=latest_id 补齐；安卓客户端用本地通知弹系统通知栏。
**痛点背景**：在线无实时触达、离线消息丢失；诉求=实时推送 + since 补齐 + 本地通知。
- 来源：REQ-010（关联 ch02 场景1）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- 连接：登录态下经 WebSocket 连接 `/ws/notify`，连接鉴权（token），按 user_id 路由。
- 推送：新站内信产生时实时推送该用户（含 latest_id/title/摘要）。
- 安卓本地通知：推送到达/站内信新增时，客户端用本地通知能力弹系统通知栏（买入/卖出信号）。
- 断线补齐：本地记录 latest_id，重连成功后按 since=latest_id 拉取站内信补齐缺口。
- 心跳保活 + 自动重连（指数退避；后台节流）。

2、实例化场景描述：

   正常场景：在线实时推送
   Given（前提条件）：用户在线且 WS 已连接
   When（行为）：select_completed 事件产生其站内信
   Then（结果）：≤5s 内客户端收到推送，latest_id 前进，安卓弹本地通知

   正常场景：断线补齐
   Given（前提条件）：断线期间产生 3 条站内信
   When（行为）：重连成功后按 since 拉取
   Then（结果）：3 条补齐，latest_id 收敛到最新，无漏无重

   异常场景：token 失效
   Given（前提条件）：连接鉴权 token 过期
   When（行为）：建立/保持连接
   Then（结果）：拒绝/断开，客户端刷新 token 重连，失败回登录页

   异常场景：心跳超时
   Given（前提条件）：长连接静默超时
   When（行为）：心跳探测失败
   Then（结果）：断开并指数退避重连（后台节流），无感恢复

   安全场景：路由隔离
   Given（前提条件）：A、B 在线
   When（行为）：推送 A 的消息
   Then（结果）：仅 A 的连接收到，B 不受影响

   安全场景：鉴权连接
   Given（前提条件）：无有效 token
   When（行为）：建立 WS
   Then（结果）：拒绝连接

   边界场景：latest_id 语义 / 后台节流
   Given（前提条件）：本地 latest_id=X；或 App 退后台
   When（行为）：重连请求 since=X / 持续无交互
   Then（结果）：返回 id>X 的消息（不回 X 本身）无丢边；WS 保活或按策略节流，回前台立即恢复同步

【操作步骤】⭐

无需用户主动操作：在线自动收推；断线自动重连并补齐；安卓通知栏点击可跳转消息/结果 Tab。

【期望效果】⭐

在线事件→客户端 ≤5s（PERF-05）；断线期间消息补齐无漏无重（REL-04）；安卓弹本地通知；连接管理不泄漏（每用户独立连接）。

【需求规格约束】🔲

通知栏跳转交互（消息/结果 Tab）。

二、非功能性验收条件 ⭐

【产品需求】

- 性能：在线消息事件→客户端收到 ≤5s（PERF-05）。
- 可靠性：消息不丢（站内信为同步源）；连接管理不泄漏（每用户独立连接）（REL-04）。
- 可测试性：可人工断开客户端连接构造断线，断言补齐消息与站内信一致、latest_id 收敛（TES-04）。

【安全需求】⭐ 必填（QS-007）

- WS 连接鉴权（无 token 拒绝）（SEC-02）；按 user_id 路由推送防串扰（SEC-01）。
- PUT 已读/补齐请求均需登录态。
- token 不写日志、不明文（SEC-07）。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
