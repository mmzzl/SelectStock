### 【Story】Story1.2.1-外部调度导入 🔴

> 来源：REQ-005（P0）

【用户故事】⭐

作为外部调度服务，我想要通过单一幂等导入接口承接选股信号落库并触发全员通知，以便每日定时选股全自动运行、无需人工干预。

【场景说明】⭐

针对每日收盘后的定时选股场景：外部调度 15:05 调用插件执行选股，再调用 `POST /select/import` 一次性导入信号；诉求=到位即落库（system 运行）+ 全员通知 + 幂等防重。
**痛点背景**：定时选股依赖命令行人工执行。
- 来源：REQ-005（关联 ch02 场景1）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- 单一导入接口 `POST /select/import`：入参 = 插件返回的信号集（幂等键 K）。
- 导入产生 system 运行（owner_type=system），对所有用户可见，完成后触发全员通知。
- 幂等：重复导入同一批数据不重复建 run（幂等键）。
- 鉴权：复用统一认证（既有 sys_users 认证体系）；导入不做选股计算、不内嵌调度。
- 鉴权失败返回 401；数据格式非法返回 4xx 不产生运行。

2、实例化场景描述：

   正常场景：首次导入
   Given（前提条件）：外部调度携带幂等键 K 与信号集；后端可达
   When（行为）：调用 import
   Then（结果）：创建 system 运行并落库（头+明细），全员可见，触发 select_completed；响应含运行 id/状态/命中数

   异常场景：幂等键重复
   Given（前提条件）：相同幂等键 K 再次调用
   When（行为）：导入
   Then（结果）：不重复建 run，返回已有运行 id，数据无重复

   异常场景：格式非法
   Given（前提条件）：信号字段缺失/类型错误
   When（行为）：导入
   Then（结果）：返回 4xx 及具体错误，不产生任何运行

   安全场景：未授权调用
   Given（前提条件）：无有效凭据
   When（行为）：调用 import
   Then（结果）：返回 401

   安全场景：越权伪装
   Given（前提条件）：普通用户构造 owner_type=system 请求
   When（行为）：导入
   Then（结果）：服务端以调用者身份/凭据判定归属，不信任开放字段

   边界场景：空信号导入 / 大批量导入
   Given（前提条件）：调度无命中信号；或单次 500 条信号
   When（行为）：导入
   Then（结果）：空信号创建 result_count=0 的 system 运行（保留留痕）；500 条 ≤5s 完成落库无丢数据

【操作步骤】⭐

外部调度服务：1. 调用插件执行选股 → 2. 携带幂等键与信号集调用 `POST /select/import` → 3. 依据响应（运行 id/状态/命中数）留痕。

【期望效果】⭐

重复导入不重复建 run；导入后全员可见并收到通知；导入吞吐 500 条信号 ≤5s（PERF-06）。

【需求规格约束】🔲

外部调度调用约定（幂等键规范）由使用者维护；导入接口不做选股计算与调度（ch06 §6.1）。

二、非功能性验收条件 ⭐

【产品需求】

- 性能：导入吞吐 500 条信号 ≤5s（PERF-06）。
- 可靠性：幂等、失败可重试（重试不造成脏数据）（REL-06）。
- 开放性：`POST /select/import` 为外部调度单一入口（OPN-02）；鉴权复用统一认证（REQ-011）。

【安全需求】⭐ 必填（QS-007）

- 鉴权强制：无有效凭据 401（SEC-02）。
- 归属防伪：owner 由服务端按调用者凭据判定，不信任客户端开放字段（SEC-01）。
- API 调用不记录 token（SEC-07）。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。

【依赖与风险】⭐

1、需求关联性，内部功能依赖：依赖 REQ-003（落库）、REQ-008（通知）、REQ-011（认证）。

3、跨团队协作（沟通/确认/附件）：外部调度服务的调用约定（幂等键）需确认。
