### 【Story】Story1.3.2-选股历史按自然日分组查询 🔴

> 来源：REQ-004（P0）

【用户故事】⭐

作为个人投资者（使用者本人），我想要按自然日分组查看历史选股运行并展开命中明细，以便复盘决策。

【场景说明】⭐

针对历史回看场景：结果 Tab 按自然日倒序分组展示运行列表（含 result_count/status/trigger_type/duration），点开展开命中明细；manual 仅属主可见，system 全员可见。
**痛点背景**：无历史功能、结果无法回看；诉求=按日分组、明细展开、分页浏览。
- 来源：REQ-004（关联 ch02 场景1/2）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- `GET /api/select/history`：按自然日倒序分组返回运行列表（含 result_count/status/trigger_type/duration）。
- 单次运行明细：`GET /api/select/run/{run_id}` 返回 code/name/signal/reason。
- 分页：运行列表分页（每页 ≤50），明细按需取。
- 可见性：manual→仅属主；system→全员（REQ-015）。

2、实例化场景描述：

   正常场景：按日分组 + 明细展开
   Given（前提条件）：存在 3 天内多次运行
   When（行为）：打开结果 Tab / 点击展开某次运行
   Then（结果）：按自然日（倒序）分组展示，运行含 status/result_count/trigger_type；展开展示全部命中明细（code/name/signal/reason）

   异常场景：访问他人 manual 运行
   Given（前提条件）：用户 B 访问用户 A 的 manual run
   When（行为）：请求明细
   Then（结果）：返回无权限语义，不泄露数据

   异常场景：空历史
   Given（前提条件）：新账号无运行
   When（行为）：打开结果 Tab
   Then（结果）：展示空态文案"暂无选股记录"，无报错

   安全场景：system 级可见
   Given（前提条件）：用户 A/B 均存在
   When（行为）：A、B 分别查询历史
   Then（结果）：均可见 system 运行；仅各自可见自己的 manual 运行

   安全场景：参数篡改
   Given（前提条件）：恶意修改 run_id 探测他人数据
   When（行为）：请求
   Then（结果）：拒绝，返回无权限语义

   边界场景：分页上限 / 同日多运行
   Given（前提条件）：历史超 100 条；或同一自然日多次运行
   When（行为）：翻页浏览 / 按日分组
   Then（结果）：每页 ≤50 条翻页完整无漏无重；同一分组内按时间倒序列出全部运行

【操作步骤】⭐

1. 打开结果 Tab（按日分组展示运行列表）。
2. 点开某次运行，展开命中明细（code/name/signal/reason）。
3. 翻页（下一页/上一页）浏览更多历史。

【期望效果】⭐

历史按自然日分组展示、明细可展开、分页正确、查询 p95 ≤1s（PERF-02）。

【需求规格约束】🔲

结果 Tab 交互稿（待交互设计阶段产出）；分页每页 ≤50 条。

二、非功能性验收条件 ⭐

【产品需求】

- 性能：历史查询 p95 ≤1s（PERF-02）。
- 可靠性：按日期索引保证查询稳定；个人量级可控。
- 可测试性：通过接口/脚本构造 N 天 M 次运行与明细，断言分组数/运行数/明细数正确（TES-03）。

【安全需求】⭐ 必填（QS-007）

- 查询强制按当前用户过滤（manual 仅属主、system 全员）（SEC-01）。
- 越权/参数篡改返回无权限语义，不泄露资源存在性。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
