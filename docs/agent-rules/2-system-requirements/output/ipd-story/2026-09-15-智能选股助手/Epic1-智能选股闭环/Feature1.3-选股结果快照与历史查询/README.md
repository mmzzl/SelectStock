## 【Feature】Feature1.3-选股结果快照与历史查询

【关联关键价值点】⭐

支撑 Epic1"结果沉淀、历史可复盘"价值：每次选股运行完整"头记录 + 明细"落库，历史按自然日分组可回看，manual 仅属主可见、system 全员可见（对应 ch02 场景1/2 的结果回看环节）。

【特性需求分类】⭐

基本可用——结果持久化与历史回看是选股闭环的必要组成，缺失则复盘不可行。

【功能级 Playbook】⭐

1、落库场景：任务开始建 select_runs 头记录（running）→ 插件返回信号逐条写入 select_results 明细（携带 run_id）→ 任务结束置终态（success/failed），更新 result_count/duration_ms/error。
2、历史回看场景：打开结果 Tab → 按自然日倒序分组查看运行列表（含 status/result_count/trigger_type）→ 点开展开命中明细（code/name/signal/reason）→ 翻页（每页 ≤50）。

【场景建模】🔲

不涉及（场景已在 ch02 场景1/2 完整描述，层级简单无需三级分解）。

【关键交互说明】🔲

- 空历史展示"暂无选股记录"空态；访问他人 manual 运行展示"无权限查看"。
- 失败运行保留头记录，结果 Tab 展示失败原因。

【特性验收条件】⭐

1. 每次运行均完整"头记录 + 明细"落库，同 run 内无重复 (code, signal)（REQ-003 验收）。
2. 历史按自然日分组展示、明细可展开、分页每页 ≤50 条（REQ-004 验收）。
3. manual 仅属主可见、system 全员可见（REQ-015）。
4. 历史查询 p95 ≤1s（PERF-02）；落库写入 p95 ≤1s（REQ-003 非功能）。

【非功能需求约束 DFX】⭐

QS-004 要求 DFX 需求基线全量落地，不满足项有 Story 跟踪。

- 性能：落库写入 p95 ≤1s（REQ-003 非功能，Story1.3.1）；历史查询 p95 ≤1s（PERF-02，Story1.3.2）
- 可靠性：明细唯一约束兜底去重（REQ-003，Story1.3.1）；数据规模增长本期不做自动清理（可达性裁剪，量级受控）
- 安全性：私有运行仅属主可读（SEC-01，Story1.3.1/1.3.2）；extra 字段不含敏感信息
- 可测试性：测试数据可构造、SQL 断言可用（TES-03，Story1.3.1）
- 可运维性：select_runs 留痕可追溯（LOG-03）；按日期索引查询
- 其他：非 XAAS，客户成功维度不涉及（QS-008 裁剪）
