# 【Epic】Epic1-智能选股闭环

【关键价值点】⭐

本 Epic 解决个人投资者（使用者本人）依赖 SSH/命令行手动执行选股、信号无法主动送达、结果无法持久化的现状。通过手机 App / PC 浏览器即可完成定时自动选股、临时手动选股、结果快照落库与历史复盘，并经由站内信/WebSocket/外部渠道主动送达信号，目标用户无需接触任何底层命令即可掌握当日与历史选股信号。

【价值实现程度】⭐

- 定时选股：收盘后由外部调度自动执行选股并全员通知，消除每日人工到点操作（场景1）。
- 手动选股：任意时刻勾选策略提交，≤2s（p95）返回 run_id，任务异步执行（PERF-03）。
- 信号主动性：选股完成后在线客户端 ≤5s 收到推送，离线由站内信补齐（PERF-05 / REL-04）。
- 结果沉淀：每次运行完整"头记录+明细"落库，历史按自然日回看，system 运行全员可见（REQ-003/004）。
- 可验收量化目标：提交响应 ≤2s、历史/站内信查询 p95 ≤1s、长任务 30 分钟内完成或置 failed（PERF-02/03/04）。

【用户需求设计结论】⭐

1、本 Epic 价值规划结论
   以"选股执行 + 结果沉淀 + 信号送达"三部分构成核心价值闭环：系统级定时选股（外部调度导入 + 全员通知）承接每日自动动作，手动选股承接临时决策；双路结果统一落库供历史回看；select_completed/select_failed 事件经由订阅策略、站内信必写、WebSocket 实时三层触达用户。

2、目标用户与现状旅程
   目标客户角色：个人投资者（使用者本人，个人自用工具）

   | 阶段 | 角色行为 | 使用工具/方式 | 痛点/感受 |
   |---|---|---|---|
   | 每日收盘后 | 登录服务器，手动执行选股插件命令行 | SSH / 命令行 | 依赖人工到点执行，错过即丢失当日信号 |
   | 决策时 | 临时换策略立刻选一次 | 命令行 + 手工记录 | 结果无持久化，历史无法复盘 |
   | 获得结果后 | 手动翻看 CLI 输出 | 终端输出 | 无法手机随时查看，信号送达滞后 |

3、用户核心痛点（按严重程度排序）
   1. **痛点 1**：选股依赖 SSH/命令行人工执行，错过当日即丢失 —— 来源：使用者自述（TR1）
   2. **痛点 2**：选股结果仅 CLI 输出不落库，无历史复盘能力 —— 来源：使用者自述（TR1）
   3. **痛点 3**：无主动通知，信号需用户主动查询 —— 来源：使用者自述（TR1）

4、设计策略
   - **设计意图**：以"外部调度驱动定时、导入接口承接落库、事件双路分发通知"解耦选股计算（不重写插件，ch06 §6.1）与执行/通知，保持后端无状态、可重启恢复（AVA-03）。
   - **设计目标**（可量化）：
     1. 提交响应 ≤2s（p95）返回 run_id（PERF-03）
     2. 事件→在线客户端推送 ≤5s（PERF-05）
     3. 历史/站内信查询 p95 ≤1s（PERF-02）
     4. 长任务 30 分钟内完成，超时置 failed（PERF-04 / REL-03）
   - **设计创新点**：信号送达采用"外部渠道 by 策略 + 站内信必写双路互备 + WebSocket 实时"三层设计（REQ-008），杜绝配置错误导致的消息静默丢失。

5、产品主场景 Playbook
   - 客户现状（痛点场景）：每日收盘后需手动登录服务器执行选股命令，否则当日信号丢失；历史结果无从回看。
   - 解决方案（价值主张）：外部调度 15:05 自动驱动选股 → 快照落库 → 站内信 + WebSocket + 外部渠道主动送达；支持任意时刻手动选股并持久化复盘。
   - 核心卖点（FAB）：功能=定时/手动选股自动执行并落库 → 优势=无需 SSH/命令行、结果永不丢失 → 收益=随时手机查看当日与历史信号，决策闭环。

6、竞品对比结论 🔲

   不涉及（个人自用工具，无商业竞品对标；现有替代方案为"SSH + 命令行手工操作"，本 Epic 的价值即替代该手工路径）。

7、关键注意事项
   - 后端不内嵌选股计算、不内嵌定时调度（ch06 §6.1），只代理查询插件并落库。
   - 选股执行为异步，前后端不做阻塞轮询（ch06 §6.2）；同一时刻全局仅 1 个运行中任务（SCA-02 / REQ-016）。
   - manual 运行归属用户、system 运行全员可见（REQ-015）；越权防护为服务端强制规则（ch06 §6.2），前端不承重隔离。
