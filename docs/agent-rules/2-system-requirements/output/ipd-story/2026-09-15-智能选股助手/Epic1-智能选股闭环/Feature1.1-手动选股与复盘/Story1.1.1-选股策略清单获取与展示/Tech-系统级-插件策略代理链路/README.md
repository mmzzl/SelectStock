# Tech-系统级-插件策略代理链路

1、【技术故事】 - TL & 模块负责人

支撑 Story1.1.1（REQ-001）的端到端策略获取链路：客户端选股 Tab → 后端代理接口 → 选股插件 `GET /api/strategy/list`。本系统作为只读代理，不落库、不维护策略，保证插件故障时客户端可降级展示而不崩溃。

关联的系统需求编号：REQ-001；依赖 REQ-011（认证）。

2、【A/C验收条件】 - TL & 模块负责人

2.1 功能性验收条件

1、业务规则、边界：
- 后端新增策略代理接口，实时代理插件 `GET /api/strategy/list`，字段按契约解析，未知字段放 extra。
- 策略数据不落库（实时查询）；仅只读，无写接口。
- 插件不可用/超时（>3s）时返回可读错误码，客户端展示降级文案。

2、系统功能约束：
- 需登录后访问（未登录重定向登录页）；绑定选股 Tab 路由。

3、实例化场景（正常场景和异常场景）：
- 正常：用户已登录、插件可用 → 打开选股 Tab → ≤1s（p95）展示策略列表（名称/说明/勾选框）。
- 异常：插件未启动 → 返回失败码 → 页面展示"选股引擎暂不可用，请稍后重试"不崩溃；超时（>3s）→ 提示"加载超时，点击重试"。

2.2 非功能性验收条件

1）性能分析：策略清单接口 p95 ≤1s（PERF-02）；选股页加载 p99 ≤3s（PERF-01）。
2）可靠性：插件故障不导致页面崩溃，错误降级可重试恢复。
3）可维护性：SELECT_PLUGIN_URL 环境变量可配，可指向测试桩（TES-02）；loguru 记录代理失败原因（LOG-01）。
4）开放性：`GET /api/strategy/list` 对接插件 HTTP 接口（OPN-03）。
5）安全性：登录鉴权；token 不写日志（SEC-07）。
6）其他：兼容 H5 浏览器矩阵（COM-02）；可测试性——mock 插件构造 3 个策略验证渲染与勾选状态。

3、【依赖与风险】 - TL & 模块负责人

1、需求关联性，内部功能依赖，外部跨团队协作：依赖 REQ-011（认证）与 stock_selector 插件接口（已存在）。
2、技术风险、测试风险：插件策略格式不固定（低）→按契约解析、未知字段放 extra；插件可用性（低）→降级展示 + 可重试。

4、【技术思路】 - TL & 模块负责人

1、技术如何实现，方案如何设计，指导开发：
   架构边界：select 模块提供只读代理路由，不内嵌选股计算（ch06 §6.1）；复用既有后端认证与日志基建；插件地址经 .env 联邦注入（LOG-02）。
2、技术方案：后端新增策略代理 API + 客户端选股 Tab 列表页（服务级 Tech 详见下方文件）；具体实现由开发负责人深化。
