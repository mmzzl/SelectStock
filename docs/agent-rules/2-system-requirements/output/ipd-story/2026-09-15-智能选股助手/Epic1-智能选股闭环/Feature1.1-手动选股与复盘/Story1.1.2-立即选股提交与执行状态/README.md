### 【Story】Story1.1.2-立即选股提交与执行状态 🔴

> 来源：REQ-002（P0）

【用户故事】⭐

作为个人投资者（使用者本人），我想要勾选策略后点击"立即选股"并获得 run_id 与可见的执行状态，以便任务在后台异步执行，完成后即可在结果 Tab 查看本次命中明细。

【场景说明】⭐

针对使用者本人的临时决策场景：想换策略立即选一次、结果要能回看。用户诉求=提交不阻塞、状态可视、结果持久化（进入 REQ-003/004 沉淀）。
**痛点背景**：手动选股只能命令行触发且阻塞等待，结果无持久化。
- 来源：REQ-002（关联 ch02 场景2）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- `POST /select/run` 提交勾选的策略列表，≤2s（p95）返回 run_id。
- 任务后台异步执行（后端代理插件 `POST /api/selector/run`），前/后端不轮询阻塞。
- 执行状态 running/success/failed 可查询；manual 运行归属当前用户（服务端生成，客户端不可覆盖）。
- 同一时刻全局仅 1 个运行中任务，已有运行时新提交被拒绝（REQ-016 单并发）。

2、实例化场景描述：

   正常场景：手动选股成功
   Given（前提条件）：已登录；已勾选"趋势回踩"等 ≥1 策略；无运行中任务
   When（行为）：点击"立即选股"
   Then（结果）：≤2s 返回 run_id，选股 Tab 显示"选股执行中"；插件返回后状态置 success，结果 Tab 可见该次命中明细（仅本人可见）

   异常场景：并发提交被拒
   Given（前提条件）：已有 1 个 running 任务
   When（行为）：再次提交选股
   Then（结果）：拒绝提交，提示"已有选股任务执行中，请稍后再试"，不产生第二个 run

   异常场景：插件失败
   Given（前提条件）：插件调用失败
   When（行为）：任务执行
   Then（结果）：重试 3 次（指数退避）后仍失败 → 状态 failed，触发 select_failed 通知（REQ-008）

   安全场景：未登录提交
   Given（前提条件）：无有效 token
   When（行为）：调用提交接口
   Then（结果）：返回 401，不创建任务

   安全场景：归属用户
   Given（前提条件）：用户 A 提交选股
   When（行为）：落库
   Then（结果）：run.owner_type=user、owner_id=A，仅 A 可见（REQ-015）

   边界场景：空策略提交 / 任务超时
   Given（前提条件）：未勾选任何策略；或任务运行超过 30 分钟
   When（行为）：提交 / 超时检查触发
   Then（结果）：空策略返回 400 提示"请至少勾选一个策略"；超时置 failed 记录 error 并触发 select_failed（REQ-016）

【操作步骤】⭐

1. 打开选股 Tab，勾选 ≥1 个策略。
2. 点击"立即选股"。
3. 观察"选股执行中"状态（running）。
4. 完成后进入结果 Tab 查看该次命中明细；失败时查看失败原因。

【期望效果】⭐

≤2s（p95）返回 run_id；状态 running→success/failed 可查；并发提交被拒有明确提示；结果进入快照落库与历史查询（REQ-003/004）。

【需求规格约束】🔲

选股 Tab + 结果 Tab 交互稿（待交互设计阶段产出）。

二、非功能性验收条件 ⭐

【产品需求】

- 性能：提交接口 p95 ≤2s（PERF-03）；选股任务 30 分钟内完成并落库（PERF-04）。
- 可靠性：长任务 30 分钟超时置 failed、失败自动重试 3 次指数退避（REL-02/03，叠加 REQ-016）。
- 可测试性：mock 插件可配延迟/失败，分别构造正常/超时/失败断言状态与耗时（TES-02）。

【安全需求】⭐ 必填（QS-007）

- 仅登录用户可提交（401 拒绝）（SEC-02）。
- manual 运行归属服务端生成、客户端不可覆盖 owner（防越权伪装）（SEC-01）。
- token 不写日志、不明文（SEC-07）。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
