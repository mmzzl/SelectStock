# Tech-系统级-任务执行治理

1、【技术故事】 - TL & 模块负责人

支撑 Story1.1.3（REQ-016）的全局任务治理体系：单并发位（同一时刻全局仅 1 个运行中任务）、30 分钟超时兜底、失败指数退避重试（3 次含抖动）、终态幂等与手工重跑准入。治理逻辑为全选股场景共享的兜底层。

关联的系统需求编号：REQ-016；叠加作用于 REQ-002/003（超时/失败行为）、触发 REQ-008（失败通知）。

2、【A/C验收条件】 - TL & 模块负责人

2.1 功能性验收条件

1、业务规则、边界：
- 单并发：全局仅 1 个 running 任务，超额提交被拒（含并发校验防竞态）。
- 超时：运行 >30 分钟置 failed 并记录 error（恰 30 分钟不算超时）。
- 重试：插件调用失败自动重试 3 次指数退避（2^n*base+抖动）。
- 终态幂等：failed/success 后重复终态写入/事件触发不产生副作用；手工重跑走新 run。

2、系统功能约束：
- 超时检测不依赖阻塞轮询外挂（定时兜底）。
- 失败触发 select_failed（REQ-008 双路分发）。

3、实例化场景（正常场景和异常场景）：
- 正常：running 期间再提交被拒；任务完成释放并发位，再次提交允许进入 running。
- 异常：运行超 30 分钟 → failed + error + select_failed 通知；连续 3 次插件失败 → 重试耗尽置 failed + 通知。

2.2 非功能性验收条件

1）性能分析：任务 30 分钟内完成并落库（PERF-04）；超时检测开销不阻塞业务。
2）可靠性：无僵尸任务（REL-03）；失败可感知（通知 + 结果 Tab 原因）；重试 3 次指数退避（REL-02）。
3）可维护性：并发/超时/重试配置环境变量化（LOG-02）；select_runs 终态与 error 留痕（LOG-03）。
4）安全性：终态幂等防重复通知（SEC-01 语义）；token 不写日志（SEC-07）。
5）可扩展性：全局单并发位为产品级 max（SCA-02）。
6）其他：可测试性——mock 插件注入延迟/失败，断言状态时序、重试次数、退避间隔符合配置（TES-02）。

3、【依赖与风险】 - TL & 模块负责人

1、需求关联性，内部功能依赖，外部跨团队协作：依赖 REQ-002/003/008；不涉及外部团队。
2、技术风险、测试风险：超时/重试边界（中）→超时兜底 + 幂等终态写入；单并发位需防竞态（如唯一 running 约束/锁）。

4、【技术思路】 - TL & 模块负责人

2、技术方案：治理调度（单并发 + 超时 + 重试）见服务级 Tech 文件；具体实现由开发负责人深化。
