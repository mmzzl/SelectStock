### 【Story】Story1.1.1-选股策略清单获取与展示 🔴

> 来源：REQ-001（P0）

【用户故事】⭐

作为个人投资者（使用者本人），我想要打开选股 Tab 即可看到后端代理插件返回的策略清单并勾选，以便随时发起选股、无需再依赖命令行。

【场景说明】⭐

针对使用者本人的选股使用场景：策略当前仅 CLI 可见，需要登录服务器才能查询；用户诉求是客户端可视化展示策略名称/说明/勾选框并可直接勾选发起选股。
**痛点背景**：选股依赖 SSH/命令行人工执行、策略不可视；诉求=可视化可勾选。
- 来源：REQ-001（关联 ch02 场景2）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- 客户端进入选股 Tab 时从后端获取策略清单（后端实时代理插件 `GET /api/strategy/list`），数据不落库。
- 策略展示含：策略名称、说明、可勾选状态；勾选数量 ≥1 才能发起选股（REQ-002）。
- 插件不可用/接口失败时展示可读错误提示，不展示空壳、页面不崩溃。
- 策略为只读代理，本系统不做策略维护，无写接口。

2、实例化场景描述：

   正常场景：策略正常展示
   Given（前提条件）：用户已登录；stock_selector 插件可用
   When（行为）：用户打开选股 Tab
   Then（结果）：策略列表在 ≤1s（p95）内展示，每项含名称/说明/勾选框，可勾选；下拉刷新可重新获取

   异常场景：插件不可用
   Given（前提条件）：插件服务未启动/地址不通
   When（行为）：打开选股 Tab
   Then（结果）：展示"选股引擎暂不可用，请稍后重试"，页面不崩溃，可重试恢复

   异常场景：接口超时
   Given（前提条件）：插件响应超过 3s
   When（行为）：加载策略
   Then（结果）：提示"加载超时，点击重试"，重试成功恢复列表

   安全场景：未登录访问
   Given（前提条件）：无有效 token
   When（行为）：访问选股 Tab
   Then（结果）：重定向登录页，不暴露策略数据

   安全场景：策略只读
   Given（前提条件）：已登录用户尝试通过策略接口写操作
   When（行为）：提交写请求
   Then（结果）：后端拒绝（无写接口），数据无篡改

   边界场景：无策略返回 / 勾选上限（>20 个）
   Given（前提条件）：插件返回空列表或大量策略
   When（行为）：加载/全选提交
   Then（结果）：空列表展示"暂无可选策略"并禁用发起按钮；大量策略全部传入运行（无硬上限）

【操作步骤】⭐

1. 打开选股 Tab（未登录先进入登录流程）。
2. 等待策略列表加载（≤1s p95）；可下拉刷新。
3. 勾选 1 个或多个策略。
4. 点击"立即选股"进入 REQ-002 提交流程（勾选数量 ≥1 才可发起）。

【期望效果】⭐

策略列表实时来自插件、可视化可勾选、错误可读可恢复、接口超时可重试；页面始终不崩溃。

【需求规格约束】🔲

选股 Tab 交互稿（待交互设计阶段产出）；策略字段未知字段放 extra 的契约解析约定。

二、非功能性验收条件 ⭐

【产品需求】

- 性能：策略清单接口 p95 ≤1s（PERF-02）；选股页加载 p99 ≤3s、无 ≥7s 页面（PERF-01）。
- 兼容性：H5 浏览器矩阵 Chrome80+/Edge79+/Safari13.1+/FF72+（COM-02）；移动端触控适配（COM-03）。
- 可测试性：SELECT_PLUGIN_URL 可指向 mock 插件，构造 3 个策略验证列表渲染与勾选（TES-02）。

【安全需求】⭐ 必填（QS-007）

- 需登录后访问（未登录重定向登录页）（SEC-02）。
- 策略数据只读代理，无写接口防篡改；token 不写日志、不明文（SEC-07）。
- 无敏感数据落库（策略不落库，实时查询）。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
