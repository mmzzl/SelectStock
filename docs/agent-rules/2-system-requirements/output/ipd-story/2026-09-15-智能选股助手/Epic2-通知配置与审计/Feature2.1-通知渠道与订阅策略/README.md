## 【Feature】Feature2.1-通知渠道与订阅策略

【关联关键价值点】⭐

支撑 Epic2"通知配置可视化可验证 + 写操作留痕"价值：四类 webhook 渠道可配置、可测试发送，订阅策略全局生效且节流防打扰，写操作结构化审计留痕（对应 ch02 场景3）。

【特性需求分类】⭐

基本可用——渠道配置是通知外发的前置能力，缺失则事件通知无处投递；策略与审计保证通知行为可控、可追溯。

【功能级 Playbook】⭐

1、配置渠道场景：设置 Tab → 通知渠道 → 新建（选择类型、填 webhook、≤3 步）→ 保存（密钥 AES-GCM 加密落盘）→ 点击"测试发送"验证可达 → 目标收到测试消息，界面反馈送达结果。
2、配置策略场景：设置 Tab → 订阅策略 → 编辑"事件→渠道类型→节流间隔" → 保存（全局生效）。
3、追溯场景：经审计查询接口/DB 检索渠道、策略等写操作留痕（操作人/时间/对象/结果，含关键字段摘要）。

【场景建模】🔲

不涉及（场景已在 ch02 场景3 完整描述，层级简单无需三级分解）。

【关键交互说明】🔲

- 删除渠道二次确认弹窗（REL-05）；webhook 地址格式实时校验；密钥输入脱敏不回显（长度 ≤200）。
- 渠道未配置的渠道类型发送静默跳过，站内信兜底（REQ-007 异常场景1）。

【特性验收条件】⭐

1. 渠道 CRUD 正常、仅本人可见、测试发送结果可反馈，新建并测试 ≤3 步（REQ-006 验收）。
2. 订阅策略全局生效；发送时按"接收用户"的本人渠道解析；未配置渠道静默（REQ-007 验收）。
3. 渠道/策略/版本/登录等写操作均产生审计记录（含人/时/对象/结果），可查询（REQ-017 验收）。
4. 渠道密钥 AES-GCM 加密落盘、不明文返回（SEC-03）。
5. 渠道/策略查询 p95 ≤1s（PERF-02）。

【非功能需求约束 DFX】⭐

QS-004 要求 DFX 需求基线全量落地，不满足项有 Story 跟踪。

- 性能：渠道/策略查询 p95 ≤1s（PERF-02，Story2.1.1/2.1.2）
- 可靠性：测试发送失败不阻塞其余操作（REQ-006 非功能，Story2.1.1）；删除渠道二次确认（REL-05，Story2.1.1）
- 安全性：渠道按 user_id 隔离（SEC-01，Story2.1.1）；密钥 AES-GCM 加密（SEC-03，Story2.1.1）；审计只追加防篡改（SEC-05，Story2.1.3）
- 可测试性：渠道/策略测试数据可构造、webhook 可指向本地 mock（TES-03，Story2.1.1）
- 可运维性：审计记录保留 ≥180 天、可配置（LOG-05，Story2.1.3）
- 其他：非 XAAS，客户成功维度不涉及（QS-008 裁剪）
