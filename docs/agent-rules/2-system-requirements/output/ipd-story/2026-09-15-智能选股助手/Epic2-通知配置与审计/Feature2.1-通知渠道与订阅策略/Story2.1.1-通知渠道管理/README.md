### 【Story】Story2.1.1-通知渠道管理 🔴

> 来源：REQ-006（P0）

【用户故事】⭐

作为个人投资者（使用者本人），我想要在设置 Tab 维护企微/钉钉/飞书/邮箱通知渠道并测试发送，以便通知链路可达、可验证。

【场景说明】⭐

针对通知配置场景：渠道 CRUD（删除二次确认）、四类 webhook、测试发送反馈送达结果、密钥 AES-GCM 加密落盘；渠道数据按用户隔离，仅本人可见。
**痛点背景**：通知配置不可视、错误配置导致消息静默丢失；诉求=可视化维护 + 测试可达。
- 来源：REQ-006（关联 ch02 场景3）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- 渠道 CRUD：新增/编辑/删除/查询四类 webhook 渠道（企微/钉钉/飞书/邮箱）；删除需二次确认弹窗。
- 渠道字段：名称（1~50 字符）、类型（枚举默认 wecom）、webhook 地址（合法 http(s) URL，格式错误实时提示）、密钥/令牌（长度 ≤200、输入框脱敏、不回显明文）、启用/停用状态。
- 测试发送：点击"测试发送"向该渠道投递一条测试消息，返回送达结果；失败返回可读原因、不阻塞保存。
- 所有渠道操作仅作用于当前用户（user_id 隔离）。

2、实例化场景描述：

   正常场景：渠道 CRUD + 测试发送
   Given（前提条件）：已登录用户
   When（行为）：新增企微机器人渠道（填 webhook）→ 保存 → 点击"测试发送"
   Then（结果）：保存成功、密钥字段加密落盘；目标机器人收到测试消息，界面反馈"送达成功"

   异常场景：webhook 无效
   Given（前提条件）：webhook 地址错误/机器人被移除
   When（行为）：测试发送
   Then（结果）：反馈失败及原因（"发送失败：xxx"），不影响渠道保存

   异常场景：删除二次确认
   Given（前提条件）：渠道存在
   When（行为）：点击删除
   Then（结果）：弹确认框，确认后删除、取消则不删

   安全场景：渠道隔离
   Given（前提条件）：账号 A 有渠道，账号 B 登录
   When（行为）：B 查询/操作 A 的渠道
   Then（结果）：不可见/拒绝，返回无权限语义

   安全场景：密钥存储
   Given（前提条件）：渠道含 webhook 密钥
   When（行为）：查看/导出接口
   Then（结果）：密钥不明文返回，仅加密存储（AES-GCM）

   边界场景：空渠道列表 / 数量较多（>50）
   Given（前提条件）：新账号无渠道；或渠道列表较长
   When（行为）：打开设置→通知渠道 / 查询
   Then（结果）：空态 + 新建引导；分页或全部展示均可，操作 p95 ≤1s

【操作步骤】⭐

1. 打开设置 Tab → 通知渠道（展示本人渠道列表，空态引导新建）。
2. 新建/编辑渠道（选择类型、填 webhook、保存）。
3. 点击"测试发送"验证可达。
4. 删除渠道（二次确认）。

【期望效果】⭐

渠道 CRUD 正常、仅本人可见、测试发送结果可反馈、新建并测试 ≤3 步（REQ-006 非功能）。

【需求规格约束】🔲

REQ-006 UI 约束：名称/类型/webhook 地址校验、密钥脱敏控件、删除二次确认弹窗。

二、非功能性验收条件 ⭐

【产品需求】

- 易用性：新建并测试 ≤3 步（REQ-006 非功能）。
- 可靠性：测试发送失败不阻塞其余操作，给出可读提示。
- 可测试性：可构造 webhook 指向本地 mock 端点，断言 mock 收到正确 payload、结果反馈一致（TES-03）。

【安全需求】⭐ 必填（QS-007）

- 渠道接口强制鉴权并按用户过滤（仅本人可见/可操作）（SEC-01）。
- webhook 密钥 AES-GCM 加密落盘、不明文返回（SEC-03）。
- 破坏性操作（删除）二次确认（REL-05）。
- 写操作审计留痕（SEC-05 / REQ-017）。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
