## 【Feature】Feature3.3-App版本管理

【关联关键价值点】⭐

支撑 Epic3"版本交付到手机"价值：启动/回前台自动检查版本，可选更新可跳过、强制更新不可跳过，Android 整包下载/MD5 校验/授权安装，H5 提示刷新，保证修复与功能迭代即时交付（对应 ch02 场景4）。

【特性需求分类】⭐

基本可用——整包升级是功能迭代交付到手机的通道，缺失则新版本无法到达用户。

【功能级 Playbook】⭐

1、版本检查场景：App 启动/回前台 → 调 `GET /api/v1/app/version` → 以 version_code（数值）比较 → 命中新版：force=false 弹"发现新版本"（以后再说/立即升级）；force=true 弹窗不可跳过。
2、Android 升级场景：点击"立即升级" → uni.downloadFile 下载（进度条）→ 校验 MD5 一致 → 引导"安装未知应用"授权 → 调系统安装 → 新版本启动。
3、H5 场景：检测到新版本仅顶部提示"有新版本，请刷新"，无下载安装。

【场景建模】🔲

不涉及（场景已在 ch02 场景4 完整描述）。

【关键交互说明】🔲

- 强制更新完成前不可进入主界面；下载失败可重试（断点续传不承诺，允许重下）。
- MD5 不一致拒绝安装并删除残留，提示重新下载。

【特性验收条件】⭐

1. 以 version_code（数值）判断新旧，非 version_name 文本（REQ-014 验收）。
2. force 策略生效：可选可跳过、强制不可跳过（REQ-014 安全场景1）。
3. 下载后校验 MD5，不一致拒绝安装并删除残留（SEC-04）。
4. H5 仅提示刷新，无下载安装；版本接口不可达静默放行不阻塞使用。
5. 版本检查接口 p95 ≤1s；下载展示进度。

【非功能需求约束 DFX】⭐

QS-004 要求 DFX 需求基线全量落地，不满足项有 Story 跟踪。

- 性能：版本检查 p95 ≤1s（PERF-02 子集，Story3.3.1）
- 安全性：MD5 完整性校验、不一致拒绝安装（SEC-04，Story3.3.1）；APK URL 由后端托管目录生成防任意路径
- 兼容性：Android"安装未知应用"授权引导（COM-04，Story3.3.1）；H5 浏览器矩阵（COM-02）；历史升级矩阵首版不涉及（COM-05 裁剪）
- 可测试性：测试 APK + 版本记录可配置（force 0/1、enabled/disabled）在模拟器验证（TES-05，Story3.3.1）
- 可运维性：版本记录 status 管理（enabled/disabled），disabled 不进入提示
- 其他：iOS 原生分发、wgt 热更新不在本期（ch06 §6.1）；非 XAAS，客户成功维度不涉及（QS-008 裁剪）
