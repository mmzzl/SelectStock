### 【Story】Story3.1.1-响应式导航外壳 🔴

> 来源：REQ-012（P0）

【用户故事】⭐

作为个人投资者（使用者本人），我想要手机底部 Tab 或 PC 侧栏导航访问选股/结果/消息/设置 4 个功能 Tab，以便同一套代码在手机与电脑上使用。

【场景说明】⭐

针对客户端外壳场景：4 主 Tab 导航，断点 <768px 底部 Tab、≥768px 左侧栏 + 顶栏；路由守卫强制登录态；消息 Tab 携带未读徽标。
**痛点背景**：无双端客户端外壳；诉求=响应式导航 + 路由守卫。
- 来源：REQ-012（关联 ch02 场景2/3）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- 4 主 Tab：选股/结果/消息/设置（消息 Tab 携带未读徽标）。
- 断点：窄屏（<768px）底部 Tab；宽屏（≥768px）左侧栏 + 顶栏（页面标题 + 用户信息）。
- 路由守卫：未登录访问业务页 → 重定向登录页；已登录访问登录页 → 直达首页；登录页/版本检查等公开路由不被拦截。
- 页面组件复用：同页面在两种形态下内容一致。

2、实例化场景描述：

   正常场景：手机 Tab
   Given（前提条件）：Android App / 窄屏浏览器
   When（行为）：打开
   Then（结果）：底部 4 Tab 导航，切换正常

   正常场景：PC 侧栏
   Given（前提条件）：宽屏浏览器（≥768px）
   When（行为）：打开
   Then（结果）：左侧栏 + 顶栏，4 Tab 可达

   异常场景：未登录直达
   Given（前提条件）：无 token
   When（行为）：访问业务路由
   Then（结果）：重定向登录页

   异常场景：窗口拉伸
   Given（前提条件）：窗口跨断点
   When（行为）：缩放
   Then（结果）：布局实时切换，无空白/重叠、不掉页

   安全场景：已登录访问登录页
   Given（前提条件）：已登录
   When（行为）：访问登录页
   Then（结果）：直达首页

   安全场景：路由白名单
   Given（前提条件）：登录页/版本检查等公开路由
   When（行为）：访问
   Then（结果）：不被守卫拦截，其余路由需登录

   边界场景：恰好 768px / 消息徽标大数值
   Given（前提条件）：宽度=768px；或未读数 100+
   When（行为）：打开 / 消息 Tab 徽标
   Then（结果）：按宽屏布局渲染无抖动；显示 99+ 或等价上限，不溢出

【操作步骤】⭐

1. 手机打开 App（底部 4 Tab）/ PC 浏览器打开（左侧栏 + 顶栏）。
2. 切换 Tab 访问各功能页。
3. 未登录时自动进入登录流程。

【期望效果】⭐

断点切换正确、4 Tab 全可达、未登录重定向登录页、高频 Tab 加载 p99 ≤3s 无 ≥7s 页面（PERF-01）。

【需求规格约束】🔲

4 Tab 交互稿（待交互设计阶段产出）；断点矩阵 375/768/1024/1440px。

二、非功能性验收条件 ⭐

【产品需求】

- 性能：高频 Tab 加载 p99 ≤3s、无 ≥7s 页面（PERF-01）。
- 兼容性：H5 浏览器 Chrome80+/Edge79+/FF72+/Safari13.1+（COM-02）；移动端底部 Tab 触控适配（COM-03）。
- 可测试性：H5 产物遍历 375/768/1024/1440px 断点矩阵断言（TES-01 测试工具表/CT-02）。

【安全需求】⭐ 必填（QS-007）

- 路由守卫强制登录态，未登录不进入业务页（SEC-02）。
- token 不写日志、不明文存储（SEC-07）。
- 登录页/版本检查等公开路由白名单管理，不暴露业务数据。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
