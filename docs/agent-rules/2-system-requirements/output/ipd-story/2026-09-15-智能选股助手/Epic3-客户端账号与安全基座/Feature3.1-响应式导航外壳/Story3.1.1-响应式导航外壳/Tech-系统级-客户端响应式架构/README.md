# Tech-系统级-客户端响应式架构

1、【技术故事】 - TL & 模块负责人

支撑 Story3.1.1（REQ-012）的客户端外壳：UniApp 应用入口按断点渲染 4 主 Tab 导航（<768px 底部 Tab、≥768px 左侧栏 + 顶栏），路由守卫强制登录态，消息 Tab 未读徽标联动站内信未读数。

关联的系统需求编号：REQ-012；依赖 REQ-011（登录）、REQ-009（消息徽标）。

2、【A/C验收条件】 - TL & 模块负责人

2.1 功能性验收条件

1、业务规则、边界：
- 4 主 Tab：选股/结果/消息/设置（消息 Tab 携带未读徽标）。
- 断点：<768px 底部 Tab；≥768px 左侧栏 + 顶栏（页面标题 + 用户信息）。
- 路由守卫：未登录访问业务页 → 重定向登录页；已登录访问登录页 → 直达首页；登录页/版本检查等公开路由不被拦截。
- 页面组件复用：同页面两形态内容一致。

2、系统功能约束：
- 断点矩阵 375/768/1024/1440px 覆盖；导航形态由同一壳组件驱动。

3、实例化场景（正常场景和异常场景）：
- 正常：手机/窄屏 → 底部 4 Tab；宽屏 → 左侧栏 + 顶栏；未登录访问业务路由 → 重定向登录页。
- 异常：窗口跨断点缩放 → 布局实时切换无空白/重叠、不掉页；已登录访问登录页 → 直达首页。

2.2 非功能性验收条件

1）性能分析：高频 Tab 加载 p99 ≤3s、无 ≥7s 页面（PERF-01）。
2）兼容性：H5 浏览器 Chrome80+/Edge79+/FF72+/Safari13.1+（COM-02）；移动端底部 Tab 触控适配（COM-03）。
3）可维护性：断点阈值与 Tab 配置常量集中管理。
4）开放性：同页面双形态复用，不引入独立端差异逻辑。
5）安全性：路由守卫强制登录态（SEC-02）；公开路由白名单（登录页/版本检查）；token 不明文存储（SEC-07）。
6）其他：可测试性——H5 产物遍历 375/768/1024/1440px 断点矩阵断言布局与 Tab 可达（TES-01/CT-02）。

3、【依赖与风险】 - TL & 模块负责人

1、需求关联性，内部功能依赖，外部跨团队协作：依赖 REQ-011/009；不涉及外部团队。
2、技术风险、测试风险：双形态渲染差异（低）→组件复用 + 断点布局 + 交互稿评审（ch06 §6.2）。

4、【技术思路】 - TL & 模块负责人

1、技术如何实现，方案如何设计，指导开发：
   架构边界：uni-app 应用外壳（4 Tab 导航 + 路由守卫 + 双形态布局）不引入后端新依赖（ch06 §6.2）。
2、技术方案：路由守卫与断点布局见服务级 Tech 文件；具体实现由开发负责人深化。
