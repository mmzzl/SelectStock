### 【Story】Story3.2.1-多账号登录认证 🔴

> 来源：REQ-011（P0）

【用户故事】⭐

作为多账号用户，我想要输入账号/密码/验证码登录 App 并自动续期令牌，以便安全进入并使用各业务功能。

【场景说明】⭐

针对登录与会话场景：复用后端认证（JWT/验证码/锁定/到期）；密码到期 428 强制改密、到期前提示剩余天数；登录失败锁定 429；token 本地存储、401 拦截 + refresh 自动续期，失败回登录。
**痛点背景**：无客户端登录，会话只能通过后端接口维护；诉求=登录/锁定/到期/续期行为与后端一致。
- 来源：REQ-011（关联 ch02 场景5）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- 复用后端认证：`POST /api/v1/auth/login`（captcha_id/captcha_code）、`GET /captcha`（图片验证码）。
- 密码到期网关：428 强制改密；password_expire_warning 到期前（≤7 天）提示剩余天数。
- 锁定策略：登录失败触发锁定，429 提示锁定时长。
- token 管理：access token 存本地（非明文敏感日志）；refresh 自动续期；401 统一拦截，刷新失败回登录。
- 登出：复用登出接口 + 本地清 token。
- UI 约束：账号 4~50 字符；密码掩码；验证码图片展示；提交期间按钮禁用；登录失败不清空账号、仅清空错误字段（密码/验证码）。

2、实例化场景描述：

   正常场景：登录成功 + token 自动续期
   Given（前提条件）：正确账号/密码/验证码；or 已登录但 access token 过期
   When（行为）：提交登录 / 业务请求 401
   Then（结果）：获得 token 进入选股 Tab，会话凭证正确存储；自动 refresh 后重放请求（≤1 次），用户无感

   异常场景：登录失败
   Given（前提条件）：密码错误/验证码错误
   When（行为）：登录
   Then（结果）：未进入，展示后端错误信息，不清空账号仅清空错误字段（密码/验证码）

   异常场景：锁定
   Given（前提条件）：连续失败达到锁定阈值
   When（行为）：再次登录
   Then（结果）：429，展示"账号已锁定，请 X 分钟后重试"

   安全场景：密码到期网关
   Given（前提条件）：密码已到期
   When（行为）：登录后发起业务请求
   Then（结果）：428 强制改密，不改密无法使用业务功能

   安全场景：登出清理
   Given（前提条件）：已登录
   When（行为）：登出
   Then（结果）：服务端登出 + 本地清 token，回登录页

   边界场景：到期前警告 / 并发会话
   Given（前提条件）：密码将到期（剩 ≤7 天）；多设备同时登录同一账号
   When（行为）：登录响应 / 同时使用
   Then（结果）：页面提示剩余天数；会话互不串扰（沿用后端会话策略）

【操作步骤】⭐

1. 打开 App（未登录 → 登录页）。
2. 输入账号/密码/验证码；提交登录。
3. 日常使用中 token 自动续期；过期需重新登录进入登录流程。
4. （可选）登出：调用登出接口 + 本地清 token。

【期望效果】⭐

登录/验证码/锁定/到期/登出行为与后端语义一致，会话管理正常；401 + refresh 续期失败回登录（REQ-011 验收）。

【需求规格约束】🔲

REQ-011 UI 约束：账号/密码/验证码字段校验、提交防重复、登录失败不清空账号。

二、非功能性验收条件 ⭐

【产品需求】

- 安全性：验证码（CAPTCHA_ENABLED 时）、锁定、到期行为与后端一致；会话：令牌不写日志、登出即失效。
- 可测试性：CAPTCHA_ENABLED=on/off 可切换，on 校验验证码、off 不校验且行为与后端一致（TES 工具表）。

【安全需求】⭐ 必填（QS-007）

- JWT + 验证码 + 失败锁定 + 密码到期网关（SEC-02）。
- 认证令牌不写日志、不明文存储（SEC-07）。
- 401 统一拦截 + refresh 自动续期；刷新失败回登录。
- 登录失败不泄露账号存在性等额外信息（沿用后端语义）。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。

【依赖与风险】⭐

1、需求关联性，内部功能依赖：依赖后端既有 auth 模块（sys_users/JWT/验证码/锁定/到期）；为所有业务接口提供会话。
2、技术风险、测试风险：验证码在不同端渲染差异（低）→复用后端 Base64 图片方案。
3、跨团队协作（沟通/确认/附件）：不涉及（复用既有 auth API）。
