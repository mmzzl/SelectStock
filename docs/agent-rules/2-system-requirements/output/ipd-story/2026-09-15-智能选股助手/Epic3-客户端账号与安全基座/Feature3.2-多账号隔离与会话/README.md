## 【Feature】Feature3.2-多账号隔离与会话

【关联关键价值点】⭐

支撑 Epic3"账号会话 + 数据隔离红线"价值：复用后端认证链路实现登录/验证码/锁定/到期/登出，提供账号信息/改密/登出自助入口，并以服务端强制归属校验保证多账号私有数据可靠隔离（对应 ch02 场景5）。

【特性需求分类】⭐

基本可用——登录为所有业务功能前置条件；多账号隔离是安全红线（SEC-01），缺失即不可用。

【功能级 Playbook】⭐

1、登录场景：打开 App → 登录页输入账号/密码/验证码 → 复用后端认证（CAPTCHA 开启时校验）→ 登录成功进入选股 Tab；access token 本地存储，401 统一拦截、refresh 自动续期，续期失败回登录页。
2、账号管理场景：设置 Tab → 查看账号信息（用户名/显示名/邮箱）→ 修改密码（旧 + 新，掩码输入）→ 退出登录（服务端登出 + 本地清 token）。
3、隔离场景：账号 A 手动选股产生运行 r1 → 账号 B 登录查看历史不含 r1、消息/渠道为空 → 外部调度导入的 system 运行 r2 A/B 均可见；B 携 A 资源 id 访问返回无权限语义。

【场景建模】🔲

不涉及（场景已在 ch02 场景5 完整描述）。

【关键交互说明】🔲

- 登录失败不清空账号、仅清空错误字段（密码/验证码）；提交期间按钮禁用防重复提交。
- 密码到期 428 强制改密，不改密无法使用业务功能；到期前 ≤7 天提示剩余天数。
- 改密两次新密码不一致本地即时提示；错误文案原样透传后端。

【特性验收条件】⭐

1. 登录/验证码/锁定(429)/到期(428)/登出行为与后端语义一致，会话管理正常（REQ-011 验收）。
2. 账号信息/改密/登出可用，密码策略提示与后端一致，密码不明文落日志（REQ-013 验收）。
3. 跨账号访问私有数据被拒绝且不泄露存在性；system 数据全员可见（REQ-015 验收）。
4. token 不写日志、不明文存储（SEC-07）。

【非功能需求约束 DFX】⭐

QS-004 要求 DFX 需求基线全量落地，不满足项有 Story 跟踪。

- 安全性：多账号数据隔离、越权返回无权限语义（SEC-01，Story3.2.3）；JWT + 验证码 + 锁定 + 到期（SEC-02，Story3.2.1）；令牌不入日志（SEC-07，Story3.2.1）
- 可用性：401 统一拦截、refresh 续期失败回登录，会话可恢复（Story3.2.1）
- 可测试性：验证码开关可配（CAPTCHA_ENABLED）可切换（TES 工具表，Story3.2.1）
- 兼容性：多端登录表单行为一致（COM-02/03）
- 其他：非 XAAS，客户成功维度不涉及（QS-008 裁剪）
