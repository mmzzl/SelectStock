# Tech-服务级-登录认证对接.md

1、【技术故事】 - 开发者（待填写）

系统级 Tech：Tech-系统级-统一认证与会话（Story3.2.1 / REQ-011）。
职责：客户端登录页对接后端 `POST /api/v1/auth/login`（captcha_id/captcha_code）与 `GET /captcha` 验证码；密码到期 428 强制改密、到期前提示剩余天数；锁定 429 提示时长的行为与后端一致。

2、【A/C验收条件】 - 开发者（待填写）

- UI 约束：账号 4~50 字符；密码掩码；验证码图片展示；提交期间按钮禁用。
- 登录失败不清空账号、仅清空错误字段（密码/验证码）；错误文案原样展示。
- 密码到期网关：改密前不可用业务功能（428）；到期提醒剩余天数（≤7 天）。
- 锁定：429 + 提示锁定时长。
- 认证行为以后端为准，客户端不自行裁决。
- 非功能：登录往返 ≤2s（p95）；CAPTCHA_ENABLED=on/off 可切换且行为一致（TES）。
- 验收：正确凭据登录成功；错误/锁定/到期各态与后端语义一致。

3、【依赖与风险】 - 开发者（待填写）

- 依赖：后端 auth API（sys_users/JWT/验证码/锁定/到期）。
- 风险：验证码多端渲染差异（低）→复用后端 Base64 图片。
