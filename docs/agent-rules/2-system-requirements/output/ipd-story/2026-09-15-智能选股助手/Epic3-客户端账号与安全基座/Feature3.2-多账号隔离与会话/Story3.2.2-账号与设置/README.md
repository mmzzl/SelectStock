### 【Story】Story3.2.2-账号与设置 🔴

> 来源：REQ-013（P0）

【用户故事】⭐

作为个人投资者（多账号用户），我想要在设置 Tab 查看账号信息、修改密码、退出登录，以便自助管理账号与密码安全。

【场景说明】⭐

针对账号自助管理场景：`GET/PUT /api/v1/auth/me` 展示账号信息；`POST /api/v1/auth/change-password` 修改密码（沿用后端复杂度/历史防重用校验、错误文案原样透传）；登出清 token。
**痛点背景**：无账号管理入口；诉求=me/改密/登出 + 密码策略提示与后端一致。
- 来源：REQ-013（关联 ch02 场景5）

---

【A/C 验收条件】

一、功能性验收条件 ⭐

1、业务规则：
- 账号信息：`GET/PUT /api/v1/auth/me` 展示用户名/显示名/邮箱（可编辑展示字段视后端支持）。
- 修改密码：`POST /api/v1/auth/change-password`（旧密码 + 新密码），沿用后端复杂度/历史防重用校验，错误信息原样展示。
- 到期提示：遵循 password_expired/password_expire_warning 响应字段。
- 退出登录：调用登出接口 + 本地清 token。
- 改密表单：旧/新/确认三字段掩码输入必填；两次不一致本地即时提示"两次输入的新密码不一致"；提交期间按钮禁用。

2、实例化场景描述：

   正常场景：账号信息展示 + 改密成功
   Given（前提条件）：已登录；旧密码正确、新密码满足策略
   When（行为）：打开设置 Tab / 提交改密
   Then（结果）：展示用户名/显示名/邮箱与 me 接口一致；改密成功后提示，后续可用新密码登录

   异常场景：策略不满足
   Given（前提条件）：新密码过短/重复历史密码
   When（行为）：改密
   Then（结果）：拒绝，展示后端原样错误信息（原样透传，无二次猜测）

   异常场景：旧密码错误
   Given（前提条件）：旧密码不匹配
   When（行为）：改密
   Then（结果）：拒绝，不改动密码

   安全场景：登出清理
   Given（前提条件）：已登录
   When（行为）：退出登录
   Then（结果）：token 清除，业务页不可再访问

   安全场景：到期引导
   Given（前提条件）：密码到期
   When（行为）：进入设置/登录后
   Then（结果）：引导改密页，业务使用前必须改密

   边界场景：到期前剩余天数 / 连续改密
   Given（前提条件）：距到期 3 天；连续提交相同新密码
   When（行为）：加载设置/登录首页 / 第 2 次改密
   Then（结果）：提示"密码将于 3 天后到期"；按后端历史防重用规则拦截/允许，与后端一致

【操作步骤】⭐

1. 打开设置 Tab → 查看账号信息。
2. 修改密码（旧密码/新密码/确认新密码，均掩码）。
3. 成功则继续以新密码登录态使用；或退出登录。

【期望效果】⭐

账号信息/改密/登出可用，密码策略提示与后端一致，密码不明文落日志（REQ-013 验收）。

【需求规格约束】🔲

REQ-013 UI 约束：改密三字段掩码、两次一致性校验、提交按钮禁用、错误文案原样透传。

二、非功能性验收条件 ⭐

【产品需求】

- 安全性：改密后会话处理与后端约定一致；新密码不明文落日志。
- 可测试性：构造失败场景，断言页面文案 = 后端返回文案（无二次猜测）。

【安全需求】⭐ 必填（QS-007）

- 改密/me 接口复用后端鉴权（SEC-02）。
- 密码不明文落日志、token 不明文存储（SEC-07）。
- 登出清理 token 后业务页不可再访问。

【海外合规】🔲

不涉及（个人自用国内工具，QS-006 裁剪）。
