# 【Epic】Epic3-客户端账号与安全基座

【关键价值点】⭐

本 Epic 提供产品客户端与账号安全的基座能力：一套 UniApp 代码响应式交付（手机底部 Tab + PC 侧栏）、多账号登录/账号设置/会话管理与数据隔离、App 整包版本管理，使所有业务功能（选股/结果/消息/设置）可承载于统一外壳之上，并保证多账号之间私有数据可靠隔离。

【价值实现程度】⭐

- 响应式外壳：一套代码编译 H5 + App，4 Tab 全可达，断点 375/768/1024/1440px 布局正确（REQ-012 / COM-02）。
- 账号会话：登录/验证码/锁定/到期/登出行为与后端语义一致，token 自动续期、过期回登录（REQ-011）。
- 数据隔离：跨账号访问私有数据 100% 拒绝且不泄露；system 数据全员可见（REQ-015，安全红线）。
- 版本交付：Android 整包下载/校验/安装（MD5），强制更新完成前不可用；H5 提示刷新（REQ-014）。

【用户需求设计结论】⭐

1、本 Epic 价值规划结论
   以"外壳承载 + 认证会话 + 隔离基线 + 版本交付"四部分支撑产品可用性：响应式导航外壳提供界面入口，复用后端既有 auth 链路提供会话，服务端强制归属校验提供数据隔离，版本管理保证功能迭代可交付到手机。

2、目标用户与现状旅程
   目标客户角色：个人投资者 / 多账号用户（使用者本人：一个主账号 + 一个测试账号）

   | 阶段 | 角色行为 | 使用工具/方式 | 痛点/感受 |
   |---|---|---|---|
   | 首启 App | 打开新装的 App | 手机 App | 无从进入应用，无登录入口 |
   | 多账号使用 | 主账号/测试账号交替使用 | 手机/浏览器 | 数据相互污染风险，私有数据泄露担忧 |
   | 换新手机 | 安装旧版后等待更新 | 手机 | 无法获得新版本，需人工拷贝安装包 |

3、用户核心痛点（按严重程度排序）
   1. **痛点 1**：多账号私有数据不隔离，测试与正式账号互相干扰/泄露 —— 来源：使用者自述（TR1）
   2. **痛点 2**：无客户端登录与会话管理，只能通过后端接口维护会话 —— 来源：使用者自述（TR1）
   3. **痛点 3**：新版本需人工拷贝安装包到手机，升级成本高 —— 来源：使用者自述（TR1）

4、设计策略
   - **设计意图**：前端不承重隔离——越权防护为服务端强制规则（ch06 §6.2）；认证完整复用后端既有链接（sys_users/JWT/验证码/锁定/到期），客户端只做对接与 401 拦截（ch06 §6.2）。
   - **设计目标**（可量化）：
     1. 4 Tab 全可达，断点切换正确，无 ≥7s 页面（REQ-012 / PERF-01）
     2. 登录/锁定/到期语义与后端 100% 一致，token 不入日志（REQ-011 / SEC-07）
     3. 越权访问全部拒绝，不泄露资源存在性（REQ-015 / SEC-01）
     4. version_code 数值比较、MD5 校验后安装（REQ-014 / SEC-04）
   - **设计创新点**：以"版本记录（enabled/disabled）+ force 策略 + MD5 校验"构建可信升级链路，下载失败可重试、校验失败拒绝安装，杜绝安装包被篡改风险。

5、产品主场景 Playbook
   - 客户现状（痛点场景）：无客户端入口，需后端接口维护会话；测试账号与正式账号数据无隔离；升级靠人工拷贝。
   - 解决方案（价值主张）：UniApp 响应式外壳 + 统一认证会话 + 服务端强制数据隔离 + 版本整包管理，形成可用可靠的产品基座。
   - 核心卖点（FAB）：功能=响应式外壳与账号安全基座 → 优势=一套代码双端交付、数据隔离可靠、升级自动化 → 收益=使用便捷、测试/正式互不干扰、新版本即时到达。

6、竞品对比结论 🔲

   不涉及（个人自用工具，无商业竞品对标；隔离与升级为平台标准能力组合）。

7、关键注意事项
   - 注册/密码找回不在客户端范围，账号由 sys_users 供给（ch06 §6.1）。
   - iOS 原生分发、wgt 热更新、UniPush/厂商离线推送不在本期（ch06 §6.1）。
   - 强制更新完成前不可进入主界面（REQ-014 安全场景）；版本接口不可达静默放行不阻塞使用。
