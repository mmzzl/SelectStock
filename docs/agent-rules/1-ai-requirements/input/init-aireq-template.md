项目在已有 `stock_selector_api`（FastAPI 开箱模板：JWT/Session 认证、RBAC、动态菜单、通知组件【企微/钉钉/飞书/邮箱 webhook】、设备示例模块）基础上，新增一套 **UniApp 客户端**，同时适配手机与电脑（同一套代码响应式，手机=底部 Tab、PC 宽屏=左侧栏）。

**核心架构认知（用户明确）：选股插件独立、我们只"查询"不下发任何计算逻辑**：

- 选股引擎 `stock_selector` 包是**独立选股插件**，以独立 HTTP 服务运行（自带 `GET /api/strategy/list`、`POST /api/selector/run`、`GET /api/health`），负责读取行情数据并给出选股信号（code/name/signal/reason）。
- `stock_selector_api` **不内嵌、不重写任何选股计算**，只做三件事：
  1. **代理查询插件**：App「立即选股」→ 后端调插件 `POST /api/selector/run` 拿信号 → 结果落库 → 展示/推送给用户。
  2. **结果存取与历史**：信号入库，按日期分组的历史结果查询。
  3. **通知**：选股完成后经通知组件推送（webhook 渠道）+ 站内信兜底。
- **定时通知**：外部独立调度服务（不进 FastAPI）定时调用选股插件拿信号，再把信号交给 `stock_selector_api` 落库+推送。
- **结果落库（已确认：运行快照模型）**：
  - `select_runs`（头表）：一次选股运行=一次快照。字段含 id(UUID 字符串)、trigger_type(manual|scheduled)、strategies(JSON 数组)、status(running|success|failed)、result_count、started_at、finished_at、duration_ms、error。
  - `select_results`（明细表）：该次运行命中信号。字段含 id、run_id(→select_runs.id)、code、name、signal、reason、extra(JSON 原样)、created_at；唯一索引 (run_id, code, signal)。
  - 结果页按 `started_at` 自然日分组展示；沿用 repositories 双实现（SQLite/Mongo 切换），不引入新存储。

核心功能：
1. **选股（接入独立插件）**：
   - `stock_selector_api` 新增「选股模块」：插件策略列表（代理 `/api/strategy/list`）、立即选股（代理 `/api/selector/run`，异步任务）、信号结果落库、历史查询。
   - 定时任务**不放进 FastAPI**——后端仅暴露一个「选股结果导入+通知」接口（`POST /select/import`），由外部调度服务在查完插件后调用；App 手动触发走代理查询插件同一链路。
   - App 结果页仅做按日期分组的结果列表，**不做个股 K 线图、不做自选股/关注跟踪**。
2. **通知**：
   - App 内提供通知渠道配置页与订阅策略配置页（复用现有 `/api/v1/notify/*` 接口，权限 `sys:notify:*`）。
   - 选股信号导入后，通过已配置的 webhook 渠道推送 + App 内**站内信**列表兜底展示。
   - 不引入 UniPush/个推厂商通道。

App 页面结构（4 个主 Tab）：**选股**（策略勾选+立即选股+任务进度+结果）/ **结果**（历史选股结果列表）/ **消息**（站内信）/ **设置**（通知渠道+订阅策略+账号信息/改密/退出登录）。
