# 插件化回测引擎 - 设计文档

> 日期：2026-09-03

## 1. 目的

为插件化量化选股系统增加回测能力。回测引擎**只负责接收信号、管理资金与持仓、记录交易、计算量化指标、落库**，
选股逻辑与仓位决策（何时买、买哪只、买多少）由选股插件/策略负责，与回测解耦。
可独立 CLI 运行，也可接入 Web。

## 2. 回测语义（资金约束组合回测 + 个股状态机）

- 初始资金（如 10 万），交易日推进
- **状态机按个股建模**：每只股票只有两个状态 `未持仓` / `持仓`，
  组合是"持仓集合 + 全局资金约束"，不存在单一"全局空仓/持仓"状态
- 买卖规则（trading_rules 的 buy/sell/add 表达式）作为**个股状态迁移**条件：

```
每只个股：
  未持仓时：
    - 买入规则满足 && 剩余资金够 && 持仓只数<N → 买入（收盘价，扣资金）→ 持仓
  持仓时：
    - 卖出规则满足 → 卖出（收盘价，释放资金）→ 未持仓
    - 加仓规则满足 && 有资金+单票未达上限 → 加仓（收盘价，扣资金）
    - 均未触发 → 维持持有（无无效调用）
```

- **每交易日顺序（组合级）**：
  1. 先对全部持仓执行**卖出**（卖出优先，避免加仓后再卖重复占资金）
  2. 再对剩余持仓执行**加仓**（受资金 + 单票上限约束）
  3. 最后用**可用资金**从候选池买入新标的（受持仓只数<N 约束）
- **资金可用性（A股 T+1）**：当日卖出释放的资金**当日不可再买**，
  记为 `available_cash`（即时可用）与 `settled_cash`（T+1 可用），次日才纳入可买资金
- **成交价**：买入/卖出均以**当日收盘价**成交（v1，用户确认；不引入随机价，保证结果可复现）
- **手续费**（用户确认）：
  - 佣金：买卖均按成交额 **万 2.5**，**单笔最低 5 元**
  - 印花税：**仅卖出**按成交额 **0.05%**
  - 买入实际扣款 = 成交额 + 佣金；卖出实际到账 = 成交额 − 佣金 − 印花税
- 多标的分散持仓：同时持仓只数上限 N（`max_positions`）
- 加仓/买入均受"剩余可用资金 + 单票仓位上限（如每票 ≤ 总资金 20%）"约束
- 整手约束（A股）：买入股数必须为 **100 股整数倍**；股数 = floor(可用交易额 / (价×100))×100，
  不足 100 股则不买（科创板/北交所 v1 统一按 100 股处理）
- 复权口径（v1）：统一使用 parquet 的 **qfq 前复权**价格；已知其价格随最新价滚动、历史时点价与当年实盘不同，
  v1 接受此失真，不额外拉后复权数据

## 2.1 个股状态机 vs 每日评估（简化说明）
原"每日对每只持仓三选一（sell/add/hold）"过度设计：
- 大部分交易日策略返回 hold，产生海量无效调用
- 引擎被迫维持"今日全部持仓→逐只评估"循环

改为**个股状态机**后（持有期间状态不复位，只在规则触发日迁移）：
- 只在规则首次满足日改变状态，无效调用归零
- 回测引擎计算量 = O(每日候选数 + 规则触发次数)，与持仓数无关
- 状态归属个股而非组合，避免"多标的持仓"与"全局空仓/持仓"语义冲突

## 4. 组件职责

### 4.1 信号接口（选股插件侧，回测不实现选股/仓位逻辑）
回测引擎按**状态机**消费两类输入：

**A. 空仓/有余力时的买入候选**：
```python
{"date": "2026-09-03", "code": "600000", "name": "浦发银行",
 "side": "buy", "target_amount": 50000, "target_shares": null}
```

**B. 持仓状态迁移指令**（仅在规则触发时产生，非每日）：
```python
{"date": "2026-09-04", "code": "600000", "name": "浦发银行",
 "side": "sell" | "add", "amount": 30000, "shares": null}
```
- `sell`: 清仓或按给定数量卖出（触发后状态迁移）
- `add`: 加仓（受资金 + 单票上限约束）
- 无 `hold` 指令——未触发规则即维持原状态（消除无效调用）

### 4.2 broker.py — 模拟账户
- 持有：可用资金 `cash`、T+1冻结资金 `settling`、持仓 positions（code → 数量+均价）、成交流水 trades
- **费用模型**：佣金 = max(成交额 × commission_rate, commission_min)；印花税 = 卖出成交额 × stamp_tax_rate
- **整手**：股数按 100 股整数倍向下取整，不足 100 股不买；费用已计入资金校验
- `buy(req)`: 校验可用资金（cash >= 成交额+佣金）且单票未达上限（每票 ≤ 总资金 × position_cap_pct，如 20%），
  按当日收盘价成交，扣 `cash`（成交额+佣金）加持仓
- `add(req)`: 成交额 + 费用后扣款，追加同一持仓（更新均价）；**不占用持仓只数配额**，仅受可用资金 + 单票上限约束
- `sell(req)`: 按当日收盘价成交，释放资金到 `settling`（T+1），金额 = 成交额−佣金−印花税；移除/减少持仓，记录已实现盈亏（费用计入 pnl）
- 卖出数量默认清仓；持仓只数上限 N 校验（仅买入新增时）
- 累计买/卖流水（含费用）供 metrics 与落库

### 4.3 engine.py — 回测引擎（个股状态机驱动）
- 逐日推进（交易日历）
- 每交易日开始：昨日 `settling` 并入 `cash`（T+1 资金到账）
- 每个交易日（顺序固定）：
  1. 当日候选池（选股插件向量化扫当日全部 parquet 产出，按优先级排序）
  2. **卖出优先**：对全部持仓检查卖出规则，触发则逐只 sell（移到 settling）
  3. 对剩余持仓检查加仓规则，触发且有资金则 add（受单票上限）
  4. 若持仓只数<N 且可用资金足够：从候选池**按排序顺序**买入，直到资金不足或达到持仓上限
  5. 记录当日净值（cash + settling + 持仓市值）供回撤/夏普
- 结束调用 metrics 生成汇总
- 性能：O(每日候选 + 规则触发次数)，与持仓数无关，无无效调用

### 4.4 metrics.py — 量化指标
- 总收益率、年化收益率（净值口径：**全资产含现金** = cash + settling + 持仓市值；年化 = (末值/初值)^(245/交易日数)-1）
- 最大回撤（基于全口径净值曲线）
- 胜率（盈利平仓数 / 总平仓数）
- 夏普比率（全口径日收益均值/标准差 * sqrt(245)）
- 盈亏比（平均盈利 / 平均亏损）、利润因子
- 交易次数（开/平仓对数）
- 平仓口径：仅统计已完整平仓（买→卖配对完成）的头寸；期末未平仓不计入胜率/盈亏比
- 说明：净值口径统一为"全资产含现金"，避免空仓现金稀释收益的误读

### 4.5 models.py — 数据结构
- `Order`: 买入/加仓/卖出请求（卖/加/买 + amount 或 shares）
- `TradeRecord`: 单笔成交（task_id, code, name, date, side, price, shares, amount, fee, pnl）
- `BacktestSummary`: 任务级汇总（strategy, params, date_range, metrics…）
- `EquityPoint`: 每日净值点（task_id, date, total_value, cash, settling, positions_value）
- 参数：`capital`(初始资金)、`max_positions`(持仓只数上限)、`position_cap_pct`(单票仓位上限比例)、
  `commission_rate`(佣金率，默认万2.5)、`commission_min`(最低佣金，默认5)、`stamp_tax_rate`(印花税率，默认0.05%)

### 4.6 策略接口（回测引擎方约定，由选股插件实现）
引擎通过两个注入回调与选股插件交互，保持解耦：
```python
def evaluate_holdings(date, holdings, df_today) -> list[Instruction]:
    """对当日所有持仓，返回触发的 sell/add 指令列表（未触发则返回空，无 hold）"""
def propose_buys(date, cash, max_positions) -> list[Order]:
    """返回当日候选买入列表（按优先级排序，受剩余资金/持仓上限约束截断）"""
```
- 数据来源：已预计算的 parquet 指标（当日截面），策略不再重算
- 选股插件读取 MongoDB trading_rules（buy/sell/add 表达式）实现上述逻辑

## 4.7 数据与边界处理（v1 规则）

- **停牌/缺失数据**：某股票当日无 parquet 行 → 视为停牌/无行情。持仓中该股当日**不可交易**
  （不触发买卖），计价用**最后可用收盘价**；未持仓则该日不产生该股候选。
- **交易日历**：从全市场 parquet 的 `date` 字段集合去重形成交易日历（升序），
  回测仅在交易日推进。
- **候选排序来源**：候选池按 `trading_rules` 的 `priority` 升序（小者优先）排序；
  同 priority 时按 `weight` 降序。选股插件的评分/破平逻辑后续可覆盖此默认排序。
- **涨跌停无法成交（v1 简化）**：v1 不检测涨跌停封板，直接按当日收盘价成交。
  已知该简化可能使涨停买不到/跌停卖不出的场景虚增收益，v1 标记为已知限制，后续版本补充分档位涨跌停检测。
- **未平仓头寸**：期末仍持仓的头寸不计入胜率/盈亏比的平仓统计（只统计完整买卖对）。

## 4.8 已知限制（v1 接受）

- 前复权 qfq 价格、无涨跌停封板检测、单笔最低佣金之外的滑点/冲击成本忽略、无费用外的印花税优惠税率
- 空仓期收益为 0，长期空仓可能使年化/夏普偏保守（夏普基于含现金全资产日收益）

## 8. 性能说明

- 信号来自已预计算 parquet 指标，回测只做"状态迁移 + 记账 + 统计"
- **状态机简化**：只处理规则触发的状态迁移，无每日无效 `hold` 调用；
  引擎计算量 = O(候选数 + 规则触发次数)，与持仓数无关
- **最大开销在选股插件的截面扫描**：每日对全市场 parquet 向量化算买入规则（一次 pandas 操作），
  非回测引擎循环
- 全市场一年 ≈245 个交易日，每日截面一次向量化 + 少量状态迁移，为秒级

## 9. 容错

- 资金不足/持仓不足/达到持仓上限：按规则跳过或拒绝，不中断
- 停牌/缺失数据：持仓不可交易、按最后价计价；候选跳过当日
- 整手不足 100 股：跳过该买入
- 单任务失败不影响其他任务
- 异常记录到日志
- 数据缺失的股票（parquet 不存在）跳过，不报错中断

## 10. 非目标（v1 不做）

- 不做选股/评分/破平/仓位决策逻辑（交选股插件策略设计）
- 不做"每日无差别扫描全部持仓"的评估模型（已简化为规则触发状态机）
- 不做止盈止损、滑点、复权遗漏处理
- 不做组合优化/风险平配（除持仓只数上限）
- 不做资金池内部的多层分配优化

## 11. 评审结论（对原始"每日三选一"的评估）

**发现的逻辑错误**（已修正）：
1. 原状态机把"组合级空仓/持仓"误当"个股状态"，与多标的分散持仓矛盾 → 改为**个股状态机**：每股只有 `未持仓/持仓` 两态，组合是持仓集合+全局资金
2. 卖出后"可能回到全局空仓"错误 → 卖出一只仅使该股回未持仓，其余持仓仍在
3. 买入不应要求"全局空仓"，而应"剩余资金够 + 持仓只数<N"（多标的下仍需继续买入）
4. 同日卖出+加仓同只冲突未定义 → 明确**卖出优先**（先卖后加，避免重复占资金）
5. **单票仓位上限未定义** → 新增 `position_cap_pct`（如每票 ≤ 总资金 20%），防止加仓滚雪球
6. **A股 T+1 资金可用性缺失** → 新增 `settling`(冻结) 与 `cash`(可用) 分离，当日卖出资金次日方可再买，避免回测收益虚高
7. 净值口径未定 → 统一为**全资产含现金**（cash+settling+持仓市值），避免空仓现金稀释误读
8. 整手约束缺失 → 股数必须 100 股整数倍，不足 100 股不买，避免非法零散股数
9. 复权口径未定 → 采用 qfq 前复权（v1 接受历史价格失真，见 4.8）
10. 停牌/缺失数据未处理 → 持仓停牌日不可交易、按最后价计价；交易日历取自全市场 parquet date 去重
11. 候选排序来源未定 → 默认按 trading_rules priority 升序 + weight 降序（4.7 可被选股插件评分覆盖）
12. 期末未平仓头寸计数口径 → 仅完整平仓对计入胜率/盈亏比

**已知限制（v1 接受，见 4.8）**：qfq 前复权、无涨跌停封板检测（涨停买不进/跌停卖不出场景收益可能虚增）、
无滑点、空仓期收益为 0。

**简化**：个股状态机——只在 buy/sell/add 规则满足日迁移状态，消除无效调用，
引擎计算量 O(每日候选 + 规则触发次数)，与持仓数无关。

**性能**：回测引擎非瓶颈；瓶颈在选股插件的每日全市场截面向量化扫描。
建议后续把"每日满足买卖规则的股票"离线做成信号表（signals.parquet），
回测即"查表 + 状态机执行"，彻底去除截面重扫。
