# 新增功能模块指南（十步）

目标：模板已把所有"脏活累活"（权限、认证、菜单、数据库切换、定时任务）做完。
新增一个业务功能只需按下面的十步照抄，全程约 10 分钟。

以「新增主机漏洞扫描任务管理 scanner」为例，演示完整流程。

## 第 0 步：约定

- 权限码格式：`<模块>:<动作>`，如 `scanner:list`
- 前端路由页面：`frontend/static/js/pages/<模块>.js`
- 实体名用单数小写（scanner），管理接口前缀用复数（/scanners）

## 第 1 步：定义数据库模型（SQL 侧，Mongo 自动兼容）

`backend/db/sql/scanner.py`：

```python
from sqlalchemy import String, Integer
from sqlalchemy.orm import Mapped, mapped_column
from db.sql.base import Base, IdMixin, TimestampMixin

class Scanner(Base, IdMixin, TimestampMixin):
    __tablename__ = "scanners"
    name: Mapped[str] = mapped_column(String(128), nullable=False, index=True)
    target: Mapped[str] = mapped_column(String(255), default="")
    schedule: Mapped[str] = mapped_column(String(64), default="")
    status: Mapped[str] = mapped_column(String(16), default="ready")
    owner: Mapped[str] = mapped_column(String(64), default="")
```

在 `backend/db/sql/__init__.py` 里 import 并加入 `__all__`，让 create_all 生效。

## 第 2 步：定义 Pydantic schema

`backend/schemas/scanner.py`，参考 `schemas/device.py`（DeviceCreate/DeviceUpdate/DeviceOut）。

## 第 3 步：建 Repository

`backend/repositories/scanner.py`：

```python
from db.sql.scanner import Scanner
from repositories._choose import pick
RepoBase = pick()

class ScannerRepo(RepoBase):
    model = Scanner
    table = "scanners"
    # 自定义查询用通用助手: await self._find_one({...}) / _find_all(...)
```

在 `backend/repositories/__init__.py` 加入单例导出：`scanners = ScannerRepo()`。

## 第 4 步：写 Service

`backend/services/scanner_service.py`，参考 `services/device_service.py`（分页/搜索 CRUD + 业务逻辑）。

## 第 5 步：注册权限码（seed）

在 `backend/db/seed.py` 的 `INIT_PERMISSIONS` 添加：

```python
{"code": "scanner:list", "name": "扫描任务列表", "module": "scanner"},
{"code": "scanner:create", "name": "新增扫描任务", "module": "scanner"},
...
```

再在 `ROLE_PERMISSION_CODES["admin"]` 里加对应 code 即可让普通管理员看到/操作。
提示：已初始化过的库需清掉 data/*.db 重建，或手工在界面补权限。

## 第 6 步：注册菜单（seed 或界面操作）

在 `backend/db/seed.py` 的 `INIT_MENUS` 添加（或登录后用菜单管理界面直接加）：

```python
{"id": "m_scanner", "name": "漏洞扫描", "menu_type": "menu",
 "path": "#/scanners", "parent_id": "", "sort_order": 3,
 "permission_code": "scanner:list", "is_visible": True},
```

## 第 7 步：写 API 路由

`backend/api/v1/scanners.py`，核心是一行权限依赖：

```python
from fastapi import APIRouter, Depends
from core.dependencies import require_permission

router = APIRouter(prefix="/scanners", tags=["漏洞扫描"])

@router.get("", dependencies=[Depends(require_permission("scanner:list"))])
async def list_scanners(q: PageParams = Depends()): ...
@router.post("", dependencies=[Depends(require_permission("scanner:create"))])
...
```

在 `backend/api/v1/router.py` import 并 `api_router.include_router(scanners.router)`。

## 第 8 步：加前端页面

`frontend/static/js/pages/scanners.js`，参考 `pages/devices.js`（表格/新增/编辑/删除），最后：

```javascript
App.registerPage('/scanners', { render: load });
```

然后在 `frontend/static/index.html` 加一行 `<script src="/js/pages/scanners.js"></script>`。

## 第 9 步：加定时任务（如需）

写 `backend/scheduler/tasks/scanner_daily.py`：

```python
from core.logger import log
from scheduler.loader import ScheduleItem

async def daily_scan(item: ScheduleItem) -> None:
    log.info("执行每日扫描任务: {}", item.title)
```

在 `backend/conf/inputs.conf` 加：

```ini
[task://scanner_daily:daily_scan]
enable = true
cron = hour=2,minute=0,second=0
```

## 发通知（通知组件接入）

模板内置通知组件：四类渠道（企微/钉钉/飞书机器人 webhook + 邮箱 SMTP）已配好接口与加密落盘，订阅策略已实现事件→渠道分发与节流。业务方要做的事极小：

### 场景一：业务事件要发通知（最常用）

**无需写任何代码**，在业务逻辑里 emit 一条 `custom` 事件即可（例如扫描发现高危漏洞时）：

```python
from services import notify_service

await notify_service.emit("custom", task="scanner_daily", score=95)
```

- 事件名可用内置的 `account_locked`/`login_failure`/`task_failed`，或自定义任意字符串
- `notify_service.emit` 完全幂等安全：策略总开关没开、事件没开、节流未到、渠道没配 → 都只是静默跳过，绝不抛错影响业务

然后在管理界面配策略：`系统管理 → 订阅策略` 打开总开关、勾选事件、选渠道。

### 场景二：内置事件当"短信/IM 告警飞报"用

登录失败、账号锁定、定时任务失败三处已自动 trigger（见 `services/account_lock_service.py`、`scheduler/scheduler_.py`），配好策略即生效，零代码。

### 场景三：新增一种渠道类型

在 `backend/services/notify/channels.py` 的 `CHANNEL_TYPES` 加一个类型（字段清单 + 敏感字段清单），在 `backend/services/notify/senders.py` 加 `send_xxx` 分支即可。发送器与渠道配置完全解耦。

### 验证与注意事项

- 先发测试消息：渠道列表点「发送测试」，或 `POST /api/v1/notify/channels/{key}/test`（邮箱渠道需带 `to` 收件人）
- 邮件走 `smtplib` 真实外呼，测试用例里用 recorder 替换发送器保证离线可跑（见 `tests/test_notify.py`）
- 密钥派生自 `JWT_SECRET`：改了 `JWT_SECRET` 后旧密文将无法解密，需重新填写渠道密码/secret
- 配置落盘位置：`NOTIFY_CHANNELS_FILE` / `NOTIFY_POLICY_FILE` / `NOTIFY_STATE_FILE`（节流状态），测试环境自动隔离到临时目录

## 小结

「模型 → schema → repo → service → 权限码 → 菜单 → 路由 → 页面」八件套 + （可选）定时任务。
其中权限码、菜单、前端页面都是"任务清单式"的机械添加，模板已把最复杂的权限引擎和双数据库适配封死。
