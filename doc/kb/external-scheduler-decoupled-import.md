## [架构约束] 外部调度不进后台（幂等导入）

定时任务由**独立外部调度服务**驱动（查外部能力 → 生成结果 → 导入业务系统），业务应用**不托管定时器**，只暴露单一幂等导入接口（`POST /select/import`）承接结果落库 + 通知。解耦触发源与业务，避免后台常驻定时任务带来的运维负担与重复调度。

## [Solution]
- 时序：外部调度 → 调用选股插件拿信号 → `POST /select/import` → 后端落库 + 通知。
- 导入接口幂等：重复导入不产生重复运行（唯一性校验/幂等键）。
- 导入运行标记为系统级（owner_type=system），全员可见并全员通知。
- 业务后台仅保留"提交即返回 run_id"的异步入口供手动触发。

## [Constraints]
- 前置：外部调度服务存在或由使用者自备（cron + 脚本）。
- 副作用：调度的健康/失败告警责任在外部侧，需求中须注明归属。
- 禁止：在业务应用内新增定时循环任务（后台托管定时器）。

## [Verification]
- 连续两次相同导入只产生一条运行记录；调度停摆不拖垮业务应用。

## [Environment]
- 语言/框架：FastAPI（导入端）+ 独立 cron/脚本（调度端）。
- 依赖：幂等校验、系统级运行标记。
